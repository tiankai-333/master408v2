# Master408 AI 工程演进记录

本文记录公开项目中 AI 能力的实施过程、技术决策和验收证据。计划性内容与已完成
内容严格分开；失败测试也会保留，避免只记录最终结果。

## 实施顺序

1. 固定评测集与 Prompt 质量、Token 成本、端到端延迟基线；
2. 模型调用、Prompt 版本和用户反馈的统一可观测链路；
3. 限流、重试、熔断、供应商降级和 429 调度；
4. RAG 混合检索、重排序与引用溯源。

顺序依据：先让质量和运行状态可衡量、可观察，再实施稳定性及检索效果优化。

## 2026-07-27：固定评测基线

### 实施前审计

- 已有 12 条测试资源，但测试只验证文件数量和分类，没有执行回答评分；
- `t_ai_usage_log` 已有 Token、费用、耗时、Prompt 版本和用户反馈字段；
- Legacy HTTP 调用能够解析供应商 usage 并写日志；
- Spring AI 主链路只有 Micrometer 调用次数和 Timer，尚未完整写入统一用量日志；
- 原测试资源包含 Java、数据库等非 408 主题，不能准确代表产品质量。

### 技术决策

- 固定数据集以版本化 JSON 保存在源码中，保证代码评审和历史复现；
- 公开数据集全部原创，不使用真题、培训资料或爬虫数据；
- 第一层评分采用确定性规则：概念覆盖、禁用表述、回答长度；
- 不默认使用 LLM-as-a-Judge，避免评测依赖外部模型、产生额外费用和评分漂移；
- 厂商未返回 usage 时使用公开公式进行 Token 估算，字段明确命名为
  `estimated*`，不作为精确账单。

### 首轮失败记录

`DeterministicAiResponseEvaluatorTest` 首次执行 4 个测试，其中 1 个失败：

- 用例手工预期混合文本 `"数组 n O(n)"` 为 5 Token；
- 按估算公式实际为 4 Token；
- 算法实现符合“一 CJK 字符一个、四 ASCII 字母数字一个、两个其他符号一个”的
  公开约定，因此修正测试预期，没有为了通过测试修改算法。

新增异步运行服务后，首次编译发现 1 个错误：

- `TaskRejectedException` 是 `RejectedExecutionException` 的子类，Java 不允许在同一个
  multi-catch 中同时捕获父类和子类；
- 改为只捕获父类 `RejectedExecutionException`，既覆盖 Spring 的任务拒绝异常，也
  保留队列满时将运行标记为失败的行为。

### 当前状态

- 已建立 `408-prompt-baseline-v1`；
- 共 12 条：9 条可执行模型用例、3 条确定性契约/失败用例；
- 已实现确定性评分、缺失概念、禁用表述、长度、估算 Token、估算费用和端到端
  延迟的数据结构；
- 已增加有界异步执行器、运行/逐条结果表、真实模型批量执行和同数据集版本对比；
- 管理端可查询数据集、启动运行、轮询结果并比较两个已完成候选；
- 管理端评测页面已完成并通过生产构建；
- 后端全量测试 53 项通过，Flyway V3 已在本地基准库验证。

## 2026-07-27：统一可观测链路

### 实施前审计

- Legacy HTTP 路径已写 `t_ai_usage_log`，Spring AI 同步和流式路径只记录
  Micrometer Counter/Timer；
- Prompt 版本引用已经随 `AiAnalysisRequest` 传递，但 Spring AI 路径没有落库；
- 数据表已有评分和反馈字段，但学生端没有带用户归属约束的反馈入口；
- 非流式接口只返回回答正文，前端无法知道反馈应关联哪一条模型调用。

### 技术决策

- 保留 Legacy 原有日志，只观察 Spring AI 路径，防止同一次调用重复记账；
- 同步调用读取 Spring AI `ChatResponseMetadata.Usage`，标记为 `provider`；
- 厂商不返回 usage 及当前流式调用标记为 `estimated`，不伪装成精确账单；
- 每次调用生成唯一 `request_id`，同时记录 engine、sync/stream、conversation、
  Prompt 版本、首 Token 延迟和端到端耗时；
- 反馈更新使用 `usage_log_id + user_id` 条件，禁止用户修改他人的调用反馈；
- 非流式 JSON 返回 `usageLogId/requestId`，流式 SSE 增加 `observation` 事件。

### 失败与修正记录

- 首次编译使用系统默认 JDK 17，Maven 报“不支持发行版本 21”；切换到项目要求的
  Temurin JDK 21 后继续验证；
- 首次读取 Usage 时假设所有 Token 字段均为 `Integer`，编译发现 Spring AI 2.0
  的缓存 Token 为 `Long`；分别安全归一化，并增加上限保护；
- 一次 `test-compile` 异常长时间没有完成，被超时终止；随后改为限定测试类并禁用
  fork，确认测试源码编译和目标测试均正常。

### 验收证据

- 可观测链路定向测试 10 项通过；
- 新增测试覆盖供应商真实 Usage、Prompt 版本与用户同表落库、反馈归属和评分校验；
- Flyway V4 已成功应用到本地 `master408_v2`，数据库结构契约通过；
- 当前数据库版本为 V4。

## 2026-07-27：模型调用稳定性治理

### 实施前审计

- Spring AI 的 OpenAI 适配层配置了 1 次内部重试，但应用层无法观察重试原因；
- 没有入口并发上限、每秒调用预算和连续失败熔断；
- 数据库已经支持按 priority 配置多个供应商，但实际调用只取第一项；
- 流式响应若无条件重试，会在部分 Token 已发送后产生重复正文。

### 技术决策

- 在应用 AI 边界统一实施稳定性策略，并关闭 SDK 隐式重试，避免重试放大；
- 用公平 Semaphore 限制同时占用模型的请求，用每秒预算对突发请求排队；
- 仅对 429、5xx、超时、连接重置等瞬时故障重试；
- 退避采用指数增长加随机抖动，并识别错误中的 Retry-After，最长等待 10 秒；
- 连续失败达到阈值后打开熔断器，冷却结束只允许半开探测；
- 主供应商失败后按数据库 priority 尝试次优供应商；
- 流式调用不自动重放；首 Token 前失败可降级，已有输出后直接结束并暴露错误；
- 所有调度、拒绝、熔断和恢复事件写入 Micrometer 指标
  `master408.ai.resilience.events`。

### 当前验证

- 稳定性及网关定向测试 5 项通过；
- 覆盖 429 两次调度后恢复、连续失败熔断、流式不重放和 Spring/Legacy 路由；
- 默认参数可通过环境变量调整，并发 16、每秒 8、最多尝试 3 次、熔断阈值 5。

## 2026-07-27：RAG 混合检索与引用溯源

### 实施前审计

- 线上查询只有 Qdrant 向量 TopK，向量开关关闭时直接返回空结果；
- `rag_retrieval_log` 和 `rag_answer_citation` 已存在，但查询流程没有写入；
- 没有多路召回融合、重排分数和回答引用状态。

### 技术决策

- 复用 MySQL `rag_chunk/rag_document`，以 ngram FULLTEXT 建立中文词法召回；
- 向量与词法各召回 `topK * 3` 候选，通过带权 RRF 去重融合；
- 重排使用 RRF、查询二元词覆盖和原始证据分数，不调用外部 Judge 模型；
- Qdrant 失败时保留 MySQL 词法结果，词法查询失败时仍保留向量结果；
- 每次检索记录用户、查询哈希、候选数、策略、耗时及最终引用候选；
- Prompt 要求回答保留 `【参考N】`，生成结束后只把正文真正提到的引用标为 used。

### 首轮失败记录

- 新增 RAG 测试首次编译时，Mockito 的 `any()` 同时匹配
  `similaritySearch(String)` 和 `similaritySearch(SearchRequest)`，产生重载歧义；
- 将 matcher 明确为 `any(SearchRequest.class)`，没有修改业务实现。
