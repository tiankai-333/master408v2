# Master408 AI 后续能力路线图

本文记录 Master408 可以继续增加的 AI 产品与工程能力。路线图不是功能许愿清单，也不代表
所有条目都必须实现；每一阶段只有在前置条件和验收标准成立时才进入开发。

现有问题及偿还顺序见 [`technical-debt.md`](technical-debt.md)，已经完成的实施证据见
[`AI工程演进记录.md`](AI工程演进记录.md)。

## 1. 路线图原则

1. **知识先于框架**：先理解问题、边界和指标，再选择 Spring AI、MCP 或其他实现。
2. **验证先于扩展**：不能通过固定数据集证明有效的能力，不进入主链路。
3. **只读先于写入**：先开放搜索、读取和规划；有副作用操作必须经过权限校验和用户确认。
4. **确定性约束模型**：模型负责理解、选择和生成，后端负责权限、参数、状态与事务。
5. **按需求引入基础设施**：Redis、MCP、消息队列和微服务都必须对应真实问题。
6. **每一步可观测**：新增模型、检索或工具调用必须同时记录延迟、错误、Token 和结果状态。

## 2. 当前能力基线

以下能力已经存在，不作为后续重复建设目标：

| 能力 | 当前实现 | 已知边界 |
| --- | --- | --- |
| 模型接入 | Legacy 与 Spring AI 双引擎 | 默认仍为 `legacy`，真实 Tool Calling 仅在 Spring AI 下启用 |
| 对话记忆 | Redis 有界消息窗口与 TTL | 会话枚举仍使用 `KEYS`，大规模下需要治理 |
| RAG | Qdrant 向量召回 + MySQL 词法召回 + 加权 RRF + 确定性重排 | 触发范围和效果仍需持续评测 |
| Tool Calling | `plan_practice` 只读规划 Tool | 当前只有一个真实 Model Tool；缺少重复调用指纹检测 |
| 写操作保护 | 草案生成与确认建卷分离 | 需持续验证幂等、权限与审计策略 |
| Eval | 固定数据集、确定性评分、版本对比 | 需要继续补充检索、路由和 Tool 专项指标 |
| 可观测性 | Usage、延迟、Request ID、反馈与部分 Trace | Agent 日志写入失败仍可能被静默忽略 |
| 稳定性 | 限流、重试、熔断、供应商降级 | 当前治理状态是单实例级 |

## 3. 推荐实施顺序

```text
M1 网页搜索与来源引用
        ↓
M2 统一意图路由与专项 Eval
        ↓
M3 通用 Tool Runtime
        ↓
M4 学习任务状态与恢复
        ↓
M5 统一身份权限与 AI 工作台
        ↓
M6 MCP 能力开放与外部能力接入
        ↓
M7 条件式高级 Agent 能力
```

M1–M3 是近期最有学习价值的主线；M4–M5 是产品与系统深化；M6–M7 只有在触发条件成立时实施。

## 4. M1：网页搜索与来源引用

### 目标

让 Agent 在用户明确要求联网、问题具有时效性或本地知识库证据不足时，能够检索公开网页，
读取可信来源并生成可追溯回答。

网页搜索定位为本地 RAG 的补充证据源，不替代经过整理的 408 知识库。

### 能力范围

第一步增加两个只读能力：

```text
search_web(query, domains, recencyDays, maxResults)
fetch_web_page(url, maxChars)
```

- `search_web` 返回标题、URL、摘要、发布时间和来源类型；
- `fetch_web_page` 读取模型选择的页面正文；
- 稳定的 408 基础知识优先走本地 Hybrid Search；
- 最新政策、考试大纲、招生信息和用户明确要求搜索的问题可以走网页搜索；
- 最终回答必须给出实际使用过的来源，而不是只展示搜索候选。

### 推荐调用链

```text
用户问题
  ↓
后端路由：是否需要外部信息
  ↓ 是
search_web
  ↓
来源筛选与 URL 安全校验
  ↓
fetch_web_page（最多读取少量候选）
  ↓
正文清洗、截断与不可信内容标记
  ↓
模型基于证据回答
  ↓
返回引用、Trace、延迟和失败状态
```

### 安全边界

- 搜索查询不得包含 API Key、完整用户画像、私密错题内容等敏感信息；
- 只允许 `http`/`https`，拒绝本地文件、回环地址、私网 IP 和危险重定向；
- 网页正文是不可信数据，不能覆盖 System Prompt、权限策略或工具规则；
- 限制页面数量、响应大小、重定向次数、单工具超时和总步骤数；
- 搜索和页面读取保持只读，不允许网页内容触发写操作；
- 来源冲突时向用户说明，不让模型自行伪造确定结论。

### Eval 数据集

至少建立四类用例：

1. 必须联网：最新政策、时间、版本和院校公告；
2. 不应联网：稳定的 408 基础概念；
3. 本地 RAG 不足后再联网：内部资料无结果或证据置信度不足；
4. 恶意网页：包含 Prompt Injection、超长正文、重定向和内网 URL。

### 验收标准

- Tool Schema、参数校验、超时和错误分类具有自动化测试；
- 路由测试可以区分必须搜索、不应搜索和信息不足三类请求；
- 来源引用能够对应到实际读取的页面；
- 页面中的指令不能改变系统行为或获得额外工具权限；
- Trace 记录查询、候选数量、读取 URL、各阶段延迟、缓存命中和失败原因；
- 在固定 Eval 上比较加入网页搜索前后的事实正确率、引用正确率、P95 延迟和成本；
- 搜索不可用时能够降级到本地知识库，或明确说明缺少最新证据。

### 实现选择

第一阶段优先采用：

```text
Spring AI Tool → WebSearchService → 搜索供应商 API
```

先把查询策略、安全和 Eval 做完整。只有当需要复用第三方 MCP Server、切换多个外部工具源，
或让多个 Agent 共用搜索能力时，再把底层接入替换或扩展为 MCP Client。

### 本阶段应掌握的知识

- Tool Schema 与结构化结果；
- 搜索召回、来源排序和可信度；
- 超时、重试、缓存、限流和降级；
- SSRF、Prompt Injection、数据泄漏与内容清洗；
- 引用溯源和搜索专项 Eval；
- 外部工具延迟分解与成本统计。

## 5. M2：统一意图路由与专项 Eval

### 目标

建立一个可解释、可测试的后端路由边界，决定请求进入普通问答、本地 RAG、网页搜索、
练习规划还是确认命令。

### 路由层次

```text
显式 UI Command
  ↓ 未命中
高精度确定性规则
  ↓ 不确定
模型结构化路由
  ↓
后端权限与参数校验
  ↓
对应执行链
```

前端按钮可以发送显式命令，但前端不再用自由文本正则决定业务意图。

### 建议的路由输出

```json
{
  "intent": "web_search",
  "confidence": 0.86,
  "source": "model",
  "needsLocalRag": false,
  "needsWeb": true,
  "requiresConfirmation": false,
  "reason": "用户询问最新考试大纲"
}
```

模型输出只是一项建议；后端仍然可以根据权限、风险和产品规则拒绝或改写执行计划。

### 验收标准

- 前端不再使用自然语言正则选择业务链路；
- 后端路由结果结构化并记录来源、置信度和原因；
- 数据集覆盖明确意图、模糊意图、否定表达、多意图和恶意输入；
- 分别统计路由准确率、误触发写操作率和不必要联网率；
- 低置信度请求能够追问或走安全默认路径。

### 本阶段应掌握的知识

- 规则路由、分类模型和 LLM 路由的取舍；
- Precision/Recall 与不同误判成本；
- Structured Output；
- Deterministic Gate；
- 离线 Eval、混淆矩阵和失败样本分析。

## 6. M3：通用 Tool Runtime

### 目标

把当前面向单个 `plan_practice` 的实现演进为能够安全管理多个 Tool 的运行时，但不为了
“平台化”提前实现动态插件系统。

### 能力范围

- Tool 名称、描述、JSON Schema 与版本；
- 参数反序列化和业务校验；
- 用户、角色、数据范围和 Tool 权限；
- 单工具超时、重试策略和错误分类；
- `tool name + normalized arguments` 重复调用指纹；
- Agent 最大步骤、Token 预算、时间预算和费用预算；
- Tool Result 大小限制、摘要和敏感字段过滤；
- 并行只读 Tool 与部分失败处理；
- Trace、Span、结果状态和审计日志；
- 只读 Tool 与有副作用 Command 的明确分离。

### 推荐 Tool 集合

| 名称 | 类型 | 副作用 | 建议策略 |
| --- | --- | --- | --- |
| `plan_practice` | Model Tool | 无 | 保留现有能力，补齐运行时治理 |
| `search_web` | Model Tool | 无 | 允许模型按路由策略调用 |
| `fetch_web_page` | Model Tool | 无 | 必须通过 URL 安全校验 |
| `search_questions` | 候选 Model Tool | 无 | 只有独立用例和 Eval 后才拆出 |
| `get_learning_profile` | 候选 Model Tool | 无 | 返回最小必要字段，防止隐私泄漏 |
| `compose_paper` | Confirmed Command | 有 | 不直接交给模型，必须用户确认和幂等 |

### 验收标准

- 测试覆盖未知工具、非法 JSON、缺失参数、参数越界、超时和重复调用；
- Tool 失败不会被模型无限重试；
- 同一确认请求重复提交不会创建多张试卷；
- 每次调用能从 Request ID 追踪到模型决策、Tool 参数、执行结果和最终回答；
- Tool 权限由后端身份决定，不接受模型自行声明角色；
- Tool Registry 是否动态化由真实需求决定，不默认读取 `ai_tool` 表注册可执行代码。

### 本阶段应掌握的知识

- Agent Loop、Stop Condition 和 Tool Execution；
- 幂等、超时、重试、补偿和部分失败；
- JSON Schema 与输入验证；
- 并发工具调用；
- 审计、权限和最小能力原则。

## 7. M4：学习任务状态与恢复

### 目标

让工作台从“连续聊天”升级为“可以暂停、确认和恢复的学习任务”，并明确区分聊天历史与业务状态。

### 状态模型

```text
Conversation History：模型看到的最近对话
Working Memory：当前推理和临时事实
Task State：练习规划、确认和执行状态
Checkpoint：中断恢复点
Long-term Memory：经过筛选的长期学习事实
User Profile：确定性学习统计和偏好
```

建议为练习任务定义显式状态机：

```text
DRAFT → WAITING_CONFIRMATION → EXECUTING → COMPLETED
  └──────────────→ CANCELLED
                         └→ FAILED / RETRYABLE
```

### 验收标准

- 服务重启后可以恢复待确认任务；
- 对话摘要不会替代真实业务状态；
- Checkpoint 与用户身份绑定，不能跨用户读取或恢复；
- 过期、取消、重复确认和执行中断都有确定行为；
- 长期记忆具备写入规则、来源、过期和删除机制；
- 错误模型输出不会直接污染用户长期画像。

### 本阶段应掌握的知识

- 状态机、事件、Checkpoint 与恢复；
- Conversation Memory 与 Task State 的区别；
- Summary、Sliding Window 与 Retrieval Memory；
- Exactly-once 幻觉、幂等执行和最终一致性。

## 8. M5：统一身份权限与 AI 工作台

### 目标

从“选择学生端或管理端登录”演进为以用户身份、角色、权限和数据范围驱动的工作台。

### 推荐边界

```text
统一身份认证
  ↓
角色与权限集合
  ↓
数据范围
  ↓
后端 API / Tool 授权
  ↓
前端按能力展示工作台
```

前端是否最终合并成一个工程是独立决策；真正的目标是权限语义统一、后端强制授权和多角色可用。

### AI 工作台形态

建议采用“上下文工作区 + 对话助手 + 可确认动作”的组合：

- 主区域展示知识图谱、题目、错题或学习报告；
- 侧边对话共享当前页面的结构化上下文；
- Tool 产生的草案使用卡片展示参数、依据、风险和确认按钮；
- 执行结果进入任务记录，而不是只留在聊天气泡中；
- 管理能力根据权限出现，不要求用户重新选择另一套身份登录。

### 验收标准

- 身份、角色、权限和数据范围具有独立模型与测试；
- API 与 Tool 使用相同的后端授权来源；
- 前端隐藏按钮不能作为唯一权限措施；
- 多角色用户的界面和操作路径明确；
- 每个有副作用 AI 动作都展示执行内容并要求确认。

### 本阶段应掌握的知识

- Authentication、Authorization、RBAC/ABAC 和 Data Scope；
- 多租户与对象级授权；
- Human-in-the-loop；
- 对话界面与任务型工作台的区别。

## 9. M6：MCP 能力开放与外部能力接入

### 进入条件

满足以下至少一项才开始：

- Master408 的能力需要被 Codex、Claude 或其他 AI 客户端复用；
- 多个 Agent 应用需要共享题库、画像或练习规划能力；
- 外部已有合适 MCP Server，直接接入优于重新开发 API 适配；
- Tool 需要跨进程独立部署和版本管理；
- 动态发现工具的收益已经超过连接、认证和运维成本。

### 两个方向

```text
对外提供：外部 AI Client → Master408 MCP Server → 只读学习能力

对内使用：Master408 Agent → MCP Client → 搜索、文件或其他外部 MCP Server
```

### 首批建议能力

对外优先暴露只读能力：

- `search_questions`
- `get_knowledge_point`
- `get_learning_profile`（必须进行用户授权和字段最小化）
- `plan_practice`

`compose_paper` 等有副作用能力暂不直接作为公共 MCP Tool，除非已经具备明确的身份传递、
细粒度授权、幂等键、确认协议和审计机制。

### 验收标准

- MCP Client/Server 完成能力协商、工具发现、调用和错误处理；
- HTTP 传输具有认证、授权、限流和审计，不能裸露在公网；
- Tool 版本变化具有兼容策略；
- 外部调用者不能绕过 Master408 的用户和数据权限；
- MCP 故障不会拖垮本地核心学习链路；
- 至少有两个真实消费者，或一个无法用普通内部调用合理解决的外部集成场景。

### 本阶段应掌握的知识

- MCP Host、Client、Server；
- Tools、Resources、Prompts；
- STDIO 与 Streamable HTTP；
- 能力发现、版本协商和连接生命周期；
- OAuth/API Key、身份传递和远程工具安全；
- MCP 与普通 Tool Calling 的边界。

## 10. M7：条件式高级 Agent 能力

这一阶段不预设必须实现，只有单 Agent 和确定性 Workflow 已经出现明确瓶颈时才进入。

### 可选方向

- Plan-and-Execute：任务确实需要先规划再分步执行；
- DAG Workflow：多个稳定步骤存在并行和依赖关系；
- Skill 渐进式加载：工具与说明数量已经造成上下文负担；
- 多智能体：角色之间存在独立上下文、权限或并行收益；
- Agent Harness：需要统一运行多个 Agent、工具、Checkpoint 和评测；
- 模型路由：简单任务使用小模型，复杂任务升级大模型。

### 禁止以名词作为立项理由

以下理由不足以启动该阶段：

- “面试最近在问”；
- “别的项目用了”；
- “框架提供了这个功能”；
- “简历上看起来更高级”。

需要用失败案例、延迟、成本、上下文长度或任务成功率证明现有方案无法满足目标。

## 11. 学习与项目结合方式

每学习一个主题，不立刻重构项目，而是完成一张概念卡：

```markdown
## 概念名称

- 它解决什么问题？
- 不使用它会发生什么？
- Master408 当前对应哪个场景？
- 当前实现是什么？
- 它与相邻概念的边界是什么？
- 有哪些失败模式？
- 用什么指标验证有效？
- 什么时候不应该使用？
- 如果实施，最小改动是什么？
```

建议学习顺序：

1. Tool Calling 完整链路；
2. 网页搜索与外部工具安全；
3. 意图路由和结构化输出；
4. RAG 与检索 Eval；
5. 幂等、重试、超时和状态机；
6. Trace、Latency、Token 和 Cost；
7. 身份、角色、权限和数据范围；
8. MCP；
9. Multi-Agent、Skill 和 Harness。

## 12. 路线图更新模板

新增能力前填写：

```markdown
### 能力名称

- **用户问题**：它为谁解决什么问题？
- **现有证据**：失败案例、用户反馈、指标或业务需求
- **当前替代方案**：为什么现有实现不够？
- **前置条件**：数据、权限、基础设施和测试准备
- **最小范围**：第一版明确不做什么
- **风险**：正确性、安全、延迟、成本和维护负担
- **Eval**：固定数据集和成功指标
- **可观测性**：需要记录的 Trace、Metric 和 Log
- **验收标准**：可以客观判断完成的条件
- **退出条件**：什么情况下停止、回滚或不再继续扩展
```

## 13. 当前推荐决策

近期只推进一条新增能力主线：**网页搜索与来源引用**。

与此同时偿还与它直接相关的技术债：统一意图路由、修复 Agent Trace 静默失败，并明确
Spring AI 主路径。完成 M1 的安全测试和 Eval 后，再决定是否扩展更多 Tool；暂不以 MCP、
Multi-Agent 或动态 Skill 平台作为近期目标。
