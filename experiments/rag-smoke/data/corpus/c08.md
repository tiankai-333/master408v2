# TCP 连接与三次握手

TCP 是面向连接的可靠传输协议。建立连接需要三次握手：客户端发 SYN，服务端回 SYN+ACK，客户端再回 ACK。三次是最少的次数，让双方都确认自己和对方的收发能力都正常。

为什么不能只握两次：若只有两次，服务端发出 SYN+ACK 就认为连接已建立，但这个确认可能在网络中迟到，服务端无法知道客户端是否真的收到了；重复的旧连接请求还会让服务端白白建立无效连接。三次握手让客户端最后再确认一次，双方的收发状态都被验证。

断开连接要四次挥手，因为 TCP 是全双工的，两个方向要分别关闭。主动关闭方进入 TIME_WAIT 状态等待一段时间，保证最后一个 ACK 丢失时对方重发的 FIN 还能被处理。

TCP 用序列号、确认应答、超时重传和滑动窗口实现可靠与流控。
