# Requirements — 新库与管理端联合设计与实施

> 归档：本文保留作历史参考，不再作为执行依据。当前入口为 [10.13 执行规格](../2026-10-13-data-admin-execution/requirements.md)；下文旧范围和流程不自动继承。

## 目标与交付物

将 9.20 尚未获整体认可的数据库设计与 9.23 管理端设计合并收敛，再交付可运行的新链路：
**采集结果 → 校验与人工确认 → 新库 → 管理端审阅与治理 → 已确认范围内的业务消费**。

最终交付：

1. **可执行的建库 SQL 与演进脚本**：不依赖私有旧库 dump，能够复现已交付模块。
2. **实际运行的独立新库**：有代表性样本、约束及验证证据，不只是 SQL 文件。
3. **可用的新管理端**：能操作已确认的首版业务，使用真实接口。
4. 与实际交付一致的 ER、字段职责、后端适配、启动与数据保全说明。

先统一目标结构与管理流程，再按业务模块逐个落地；不要求一次建齐所有表。
本文件不授权立即修改数据库、业务代码或公网环境。进度只记录于 [roadmap](../roadmap.md)。

## 需求

| 编号 | 必须得到的结果 |
| --- | --- |
| IA-01 | 一张目标 ER、表职责与复用清单、代表性题目落库样例、数据流和管理端页面/操作映射。ER 区分实际外键、逻辑引用与 JSON 内引用，不把图中的关系当作数据库已经强制的约束。 |
| IA-02 | 新库初始化与增量演进有单一受控来源，遵守 Flyway 约束，不改写已提交旧迁移。明确一次性 SQL 与可重入迁移命令的区别；空环境能初始化，已有新库能增量升级并保留数据。仅初始化必要配置与安全注入的管理员，不复制旧题库/答卷。 |
| IA-03 | 内容只经校验后的采集管道写入。HTML 安全处理、选项/答案/解析完整性、五题型编码（3=判断、4=填空）、来源、批次及授权状态有规则；纯文本从事实源生成，不成为第二份独立内容。缺答案与缺图按题型和就绪规则处理，不伪造补齐。 |
| IA-04 | 导入支持校验、人工确认、提交、结果查询和明确重试；确认绑定操作者与确切载荷，提交端重新校验。稳定来源身份、同源变更、重复请求、并发与失败恢复有确定行为。采用符合 D-33 的最小记录结构，不为旧设计引入版本机器或完整任务平台。 |
| IA-05 | 管理端能登录、筛选题目、完整预览、查看来源与导入结果、执行已确认治理操作；空态、失败、未就绪状态真实呈现。试卷及其他管理能力按首版范围表落地，无假成功按钮，不用禁用菜单冒充交付。 |
| IA-06 | 停用、恢复、紧急撤下的对象与影响明确；新组卷、检索、进行中作答和历史展示分别定义。涉及作答的模块采用 D-33 的作答时快照方向，保证题面、评分依据与历史一致，不再规定绑定 question_content 版本行。 |
| IA-07 | 明确既有知识库/RAG 的复用边界；新题投影追踪源身份、内容摘要和生成规则，失效后可重建。展示、词法、向量就绪分别表达；只适配已确认消费者，不重建检索引擎或承诺质量提升。 |
| IA-08 | 复用 admin 专属认证，验证双端并行登录/独立退出；写接口执行后端授权。新库、后端 profile、缓存/索引/资源隔离，账号最小权限，日志与仓库不含口令。旧端和旧库保持可用，不执行旧迁移/回填/删表。 |
| IA-09 | 已确认模块能在独立环境启动、演示、停止写入和回退兼容应用，保全新数据。公网切换另行确认；把入口切回旧端不能宣称旧端可读新数据。 |
| IA-10 | 用户接受联合设计、首版范围全部技术验收、作者自我考核通过，三项分别记录。旧实验仅作限定条件下的证据，不能直接充当新链路验收。 |

## 联合设计评审要回答的问题

结果直接补在本文件或链接的设计材料中，不再建立多套决策台账：

- **范围与复用**：首版必须完成哪些操作？用户/学科/知识库/试卷/作答等哪些结构复用，哪些只保留接口，哪些不纳入？逐项对应表、服务、页面与模块。
- **具体数据**：普通题与含图、多小问题分别写入哪几行？选项如何展示、答案如何判分、图片从哪里加载？明确保留 D-33 不做块级结构化的局限。
- **同源更新**：v0 的“raw 不可变／整行替换”需要说明身份是否稳定、试卷引用如何保持、历史快照与投影如何处理；不能靠删除重插暗中决定，也不能据此恢复已撤销的版本机器。
- **导入规则**：source_ref 的粒度能否区分同页多题？缺失身份如何处理？重放、同源变更、失败项重试、确认失效与事务边界如何区分？
- **运行边界**：先做哪个模块、依赖什么？新库名、连接、初始化、资源与回退边界是什么？用户域等依赖如何补齐，不依赖旧库隐式兜底？

整体评审确认首版范围、实体关系和主要流程；后续模块只补自身字段/API 细节，不预设计所有未来表。
已有 D-33 等明确决定直接继承，不重复拍板；仅确认未明确的后果与冲突。

## 非目标与学习目标

非目标：旧库迁移或删除、全系统重写、重建学生端、人工题目编辑器、复杂 RBAC、主观题评分写功能、
CLI、MCP、Agent Loop、多智能体、RAG 黄金集/效果专项、对象存储迁移及公网自动切换。
这些不作为 9.27 的完成门槛。真实抓取、模型调用与公网发布另行确认范围和成本。

学习问题：为什么这些表需要重建而另一些复用？如何从一题追踪到显示、判分和检索？
重复导入与更新有什么不同？没有版本表时如何保护历史？如何从空环境复现并证明旧环境未受影响？
自我考核见 [validation](validation.md)。
