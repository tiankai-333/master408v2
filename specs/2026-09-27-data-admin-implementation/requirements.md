# Requirements — 新库与管理端联合实施

## 目标

把数据库架构设计与管理端设计落成一套可运行、可验证的系统：**爬虫采集 → 管道校验 → 人工确认 → 新库版本化写入 → 管理端审阅与治理 → 学生作答及 RAG 消费**。

本 Feature 是实施规格，不重新开展全套架构设计。当前任务只建立规格，实际开发、环境写入与发布按后续授权执行。进度只记录于 [roadmap](../roadmap.md)。

## 设计依据与决策

| 编号 | 执行依据与边界 |
| --- | --- |
| E-01 | 用户要求将两份设计汇总为新的实施 Feature；数据库以 [requirements 的 D-29～D-31](../2026-09-20-database-architecture/requirements.md) 为最新依据：新库并行、旧库不动、爬虫为题目内容唯一合法来源。 |
| E-02 | 继承 [数据契约](../2026-09-20-database-architecture/appendix/data-contract.md)、[物理设计候选 1～11](../2026-09-20-database-architecture/appendix/physical-design.md) 和复杂题样本约束；候选尚未实现或验证的部分必须在本 Feature 落地测试，不能继承“已通过”的结论。 |
| E-03 | 管理端继承 [页面清单](../2026-09-23-admin-redesign/scope-and-pages.md)、[流程](../2026-09-23-admin-redesign/flows-and-wireframes.md)、[API 契约](../2026-09-23-admin-redesign/api-contract.md)、[工程架构](../2026-09-23-admin-redesign/architecture-and-cutover.md)。使用 `apps/frontend/admin-next`，Vue 3 / Vite 6 / Element Plus / Pinia / Router / Axios；沿用设计默认 JS，不顺手升级其他工程。 |
| E-04 | D-31 取代管理端旧设计中“编辑器以后恢复”的默认假设：本期不提供题目内容编辑；修复通过修正采集源或转换规则后重导入，不让 AI 编造源内容。人工知识点关系、状态操作仍保留。主观题评分写接口仍按管理端首版边界延后，本期只读展示。 |
| E-05 | D-29 取代旧设计中迁移回填、兼容双写、同库前端切回的执行前提；不复制旧题库与历史答卷，不删除旧库，不假设旧端能读取新库。共享非题目业务所需表须显式建模与初始化，不能依赖私有旧库 dump 才能启动。 |
| E-06 | 整体设计已经确定，实施按可验收批次推进；不能以一个垂直切片替代首版完整交付。生产入口整体切换另经发布确认，本 Feature 先交付隔离环境中完整可验收的新链路。 |

## 实施需求

| 编号 | 必须实现的结果 |
| --- | --- |
| IA-01 | 新库从空库可重复引导，包含业务启动所需表、候选 1～11、枚举及 JSON schema 文档；新库迁移链独立配置，保留已提交旧 Flyway 脚本及旧库历史，不改写它们。初始化管理员凭据安全注入，不写固定密码。 |
| IA-02 | 落实 D-30 七项：自解释 schema、约束错误映射、批次血缘、只读对账、显式状态与错误、reader/writer/admin 最小权限账号、独立沙箱。AI 不持生产 DDL 权限，不获得数据库口令。 |
| IA-03 | 题目内容权威写入只走采集管道；五题型、块顺序及归属、来源引用、资源校验、答案与解析保持契约；纯文本及标志由服务端重算，展示与检索投影不得独立改成第二份事实。 |
| IA-04 | 写入在同一事务内锁定稳定题目身份、校验 expectedVersion、推进版本与 current；唯一键保证至多一个，事务与使用入口校验保证有效题有可用版本。失败不留下半份内容，并发冲突返回可机读原因。 |
| IA-05 | 管道提供 validate / commit / jobs / job detail 及薄 CLI；dry-run 无持久副作用，提交须人工确认且服务端重新校验。幂等键、载荷摘要、逐题事务、作业留痕与失败重试构成闭环；确认绑定操作者与确切载荷，不能换内容复用确认。 |
| IA-06 | 管理端按 P1～P17 清单交付，排除 P3 题目编辑器：共 16 个页面标识（含登录；15 个非登录页面）。工作台、题库审阅、版本、资源来源、作业、RAG、考试运营、AI 治理及系统管理均使用真实接口；无假成功按钮。知识点人工整理的入口及契约在批次 0 补齐。 |
| IA-07 | 停用、恢复、紧急撤下、发布标记及知识点留痕遵循既定状态机；过滤覆盖新组卷、作答入口与检索，历史引用按设计保留，不级联物理删除。 |
| IA-08 | 开始作答建立 attempt 与逐题版本映射，刷新恢复与重复开始幂等；交卷、判分及历史回显使用绑定版本，不在交卷时重新选 current。学生端仅做支撑这些契约所必需的适配。 |
| IA-09 | RAG 记录源版本、块、资源、生成规则与一致的 hash 基准；展示就绪、词法召回、向量状态、最终过滤分别验证。过期投影不得冒充当前版，失败可对账与重建，不重写检索引擎或宣称质量提升。 |
| IA-10 | 新端复用 admin 专属认证，复验学生/管理员并行登录和独立退出；新增写接口校验后端身份、角色与数据范围。环境、库、资源与缓存命名空间明确隔离，旧链路不受影响。 |
| IA-11 | 提供新环境启动、停止写入、应用回退及数据保全操作说明；应用回退不等于数据库降级，不能把删除新表当作有数据环境的回滚。公网部署复用 public-deploy 流程，未经确认不改公网入口。 |
| IA-12 | 全部验收有命令、环境、版本、样本及限制；完成技术验收和作者自我考核后才关闭 Feature。原设计 Feature 的考核状态不被自动关闭。 |

## 开工前必须收口的实施细节

在批次 0 将结论补入本文件决策表，不用代码暗中决定：

1. 新库名、连接 profile、独立后端端口、资源目录、Redis/Qdrant 隔离方式；新端与验证用学生端只连新后端。不得由请求参数任意选择数据库。
2. 新库独立 Flyway location 与基线版本策略、非题目领域必需表和最小初始化数据清单。
3. `import_batch` 与作业/逐题记录的关系、来源稳定键及去重规则；作业记录不重复成为另一套内容存储。
4. 原契约“同键返回原结果”与“同键重试失败项”存在歧义。建议区分原请求重放与显式失败项重试：保留同一作业身份，为重试操作分配独立请求身份，只执行未成功项；定稿前不得直接实现自动重跑。
5. 确认凭据有效期、批量上限、事务锁顺序、冲突码/HTTP 映射、中断恢复与审计落库原子性；发布动作和知识点标注的管理入口。
6. 候选结构与来源 sample 若存在冲突，记录具体字段和影响后确认；原设计自我考核未完成不冒称已验收。

## 非目标

旧库迁移/回填/删表、重建学生端、人工题目编辑器、主观题评分写功能、复杂 RBAC、MCP、多智能体、对象存储迁移、检索效果专项优化、全量抓取或未授权题库入仓库。默认测试使用明确标注的原创同结构夹具，真实样本按授权在本地核验。模型真实调用、外部抓取及公网发布分别确认范围与成本。
