# Plan — 新库与管理端联合设计与实施

> 归档：此计划停止推进，保留原文。后续按 [10.13 执行计划](../2026-10-13-data-admin-execution/plan.md) 逐轮确认，不继续本文件的任务组。

顺序：**联合设计与用户确认 → 按模块实施并演示 → 整体验收与自我考核**。
不沿用“设计已完成，直接建齐全部候选表”的六批计划。进度只进入 [roadmap](../roadmap.md)。

## 1. 收敛联合设计（IA-01、IA-06～08）

1. 只读核对已有 SQL/ER v0、实际表结构与关键消费者，复用已有审计；只补影响当前决策的缺口，不重跑全库研究。
2. 在 requirements 列首版范围与复用清单：业务操作 → 表/服务/API/页面 → 原样复用/适配/新建/不纳入。
3. 完善目标 ER、表职责及数据流，以普通题和含图多小问题说明实际落库与页面效果；可复用授权本地样本，原创夹具须明确标记。
4. 收口同源更新、来源身份、快照、派生失效和运行隔离问题，与管理端流程一起审阅。
5. 向用户展示结果，记录明确的接受/修改意见，确认模块顺序和首版完成边界。

出口：用户能回答“需要哪些表、为什么、怎么使用、哪些不动”，并接受联合设计。
现有 SQL/ER 可完善，不必另起一套；确认前不开始业务代码或建库实施。
未纳入首版模块明确去向，不以“以后补”掩盖启动必需依赖。

## 2. 按业务模块交付（IA-02～09）

默认先做**最小题库闭环**：必要的认证/学科依赖 → 少量题导入 → 管理端列表、预览和来源/结果查询。
之后按接受的范围推进试卷、治理及必要消费者适配；具体拆分随第 1 组确认，不预建所有未来表。

每个模块只跑一轮相同流程：

1. 明确可演示的用户操作，补齐本模块字段、约束、事务、API 与错误契约，复用已有基础。
2. 交付相应 SQL/增量脚本，在独立测试库验证，再接入实际新库环境；不改旧迁移、不写旧库。
3. 实现或适配最小服务与管理端流程，使用真实接口；随模块补必要种子数据与启动配置。
4. 跑正常路径与关键反例：重复/变更导入、失败回滚与恢复、未授权操作、缺内容/资源等，按模块选择。
5. 展示一条真实操作和对应数据库结果，记录用户验收意见；修正后再推进依赖模块。

演示前保持设计、SQL、实际库、接口和页面一致。独立模块无需等待无关模块；
跨模块身份/关系/范围变化先确认影响。涉及作答或检索，补快照或投影一致性验证，不能因复用而跳过。
不为导入另造 CLI，不把全部旧后台页面作为默认任务。

## 3. 整体交付与考核（IA-09/10）

1. 从空的独立环境复现确认的首版：引导 SQL/迁移、配置、样本、新后端与管理端；验证增量升级不丢新数据。
2. 核对范围表：每个首版操作有真实实现、证据与用户验收，不用单模块演示代替整体完成。
3. 验证旧环境保护、双端认证、故障停写、兼容应用回退与数据保全；记录环境边界，公网切换另行授权。
4. 按 validation 由作者独立讲述、追问与实践，记录提示和复测，不替作者作答。
5. 同步 roadmap；保留历史实验，仅引用仍适用的限定结论，不改写旧实验制造“全部通过”。

出口：可执行 SQL、实际新库、可用新管理端与配套说明交付，用户验收及自我考核通过。
文档写完、任务跑完、测试全绿，任何单项都不是 Feature 完成条件。
