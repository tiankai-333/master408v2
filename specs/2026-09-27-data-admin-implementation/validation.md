## 一条完整验收故事

采集一组含多图、多小问的样本 → dry-run 指出一题资源缺失 → 修源后重新校验 → 人确认后提交 → 管理端按作业预览 → 学生开始作答绑定 v1 → 重导入产生 v2 → 原答卷仍按 v1 判分与回显 → RAG 展示 v2 的真实就绪状态 → 停用该题后新选题和检索排除它，既有历史保留。

另跑一批“成功项＋坏题＋并发冲突题”，验证失败隔离、重复请求、失联恢复和明确重试。小样本通过不代表全量导入或性能容量已验证。

## 自我考核

1. 为什么新库仍需要版本、事务与唯一约束？“最多一个 current”和“必须有一个”分别由谁保证？
2. AI 说校验通过之后，为什么 commit 还要校验？同请求重放与失败项重试有什么不同？
3. 题目重导入后，如何保证学生看到的题面和评分答案属于同一版本？现场追踪一次 attempt。
4. 管理端不编辑内容，如何修复错误题？说明源、规则、版本、资源与 RAG 的变化。
5. 实践：独立定位一条失败作业、修复输入并安全重试；再解释回退应用为何不能恢复旧库中不存在的新数据。

考核须记录提示和薄弱点；允许查代码，不以复述 AI 答案代替掌握。原设计未关闭的考核可引用本次对应证据，但需逐项确认，不自动勾选。
