# Validation — 学习任务执行与多端验收

以下为目标，未执行。第一组先确定同一条任务的输入、记录和成功判据。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 正常任务 | 适用的讲解有可回看证据；练习草案经确认后形成可作答记录，交卷结果可再次读取 |
| 意图不明/无题 | 澄清或说明缺少条件，不虚构题目、不误称已建卷 |
| 确认边界 | 取消不产生确认动作的业务写入；相同确认重放返回稳定结果，不多建试卷；改参数不能复用旧确认 |
| 用户边界 | 当前用户身份由后端绑定，不能确认或读取他人任务/答卷 |
| 工具与模型失败 | 参数无效、供应商失败、重复调用或循环/预算耗尽均明确终止或受控降级，不继续误写 |
| 内容与结果一致 | 题库更新、恢复作答和历史回看按已确认策略保持题面及评分依据一致 |
| 追踪与演示 | 从请求定位实际路由、调用、确认、业务记录和最终结果；单条日志不冒充整条 Trace |
| 多端 | 按确认的版本/功能矩阵验证 Web 完整场景及小程序适用路径，实际入口、版本与后端环境相符 |

本地确定性测试、真实模型、Web、公网和微信真机分别记录；未跑的平台保留未验证。
小程序若不提供 AI 入口，不宣称其已上线 Agent；若不纳入本期，先明确该范围及简历措辞。
复用旧验证仅支持原版本原条件，不能自动证明新数据链路通过。

## 自我考核与完成

作者独立追踪一次请求至答卷，解释谁决定调用、谁执行、谁批准写入，以及循环为何终止。
实践复现重复确认或一次工具失败，说明数据库与用户界面的实际结果。
选定任务的正常与关键失败路径通过、约定多端范围有证据且作者考核通过后关闭本项。
