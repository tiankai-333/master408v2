## 第 2 轮：意图路由现状与形态决策（2026-10-21）

### 用户诉求与核实事实

用户指出：当前意图路由很糟糕，完全是纯规则的；但至少有一个编排器。只读核对确认：

- 路由实际有三层规则：前端 `knowledge-graph/index.vue` 用与后端相同的正则预先分类并发显式 intent；
  后端 `AiIntentRouter` 再用 `练习|组卷|出题…`、`学习画像|薄弱点…` 等中文正则路由；
  confidence 0.9/0.95 为按规则顺序写死的常数。
- 模型路由（`SpringAiToolOrchestrator`）仅在 `RouteSource.FALLBACK` 时进入；其 system prompt
  自定位"意图路由器"，带四轮 ToolCallingManager 循环、只读 `plan_practice`、AgentRunRecord 留痕——
  骨架真实可用，是最应复用的资产。
- 候选场景"先讲解进程调度，再安排三道练习"在前端正则即命中"练习"，直接产出练习草案，
  讲解半句被静默丢弃；即使走到模型路径，`Outcome` 草案与文本互斥、prompt 不含 context
  与会话记忆、循环耗尽静默取末次回答，组合意图仍无法完整表达。

### 本轮决策

用户在两个方案中选定**工具循环兼任路由**：

- auto 自由文本默认进入既有 `SpringAiToolOrchestrator` 工具循环；路由由模型"是否调用工具"表达；
  澄清先以文本追问实现，不新增工具、不做独立路由调用。
- 前后端业务意图正则删除；规则退为护栏：显式 UI Command 直派、上下文短路（贴题即讲题）、
  空输入安全默认。写操作防线不变，建卷仍只经 `/agent/confirm`。
- 需补的缺口：prompt 装入 context 与会话记忆；Outcome 允许草案与讲解并存；
  循环耗尽显式终止并留痕。

### 接受的代价

- 路由与执行纠缠，无法输出孤立混淆矩阵；评测退为端到端行为矩阵
  （工具触发/未触发/追问/直答，从 AgentRunRecord 的 toolCallJson 统计）。
  Phase 7 的孤立路由器与专项评测集不在本 Feature 范围。
- 每条 auto 文本均调用一次大模型，不再存在零成本正则路径；成本随真实模型验收一并记录。

## 第 3 轮：任务组 1 全链路只读核对（2026-10-21）

### 链路事实（代码只读核对，未执行任何业务操作）

确认→建卷：`/agent/confirm`（web 与 wx 各一端点）→ `AiAgentPlannerServiceImpl.confirm()` →
`AiPaperComposeService.compose()`（`@Transactional`）→ 旧库 `t_exam_paper`（限时卷）+
个人任务（`t_text_content` + `t_task_exam`）→ 学生按既有考试主流程作答、交卷、回看（均旧库）。

- **确认不幂等**：`confirm()` 每次调用都新建试卷；无服务端待确认状态，questionIds 由客户端
  回传，重放同一确认会重复建卷（默认卷名按计数递增）。直接违反 D-04 与 validation 确认边界场景。
- **草案未服务端留档**：`plan()` 仅写 AgentRunRecord 日志；confirm 的 questionIds 未与已出
  草案绑定校验，客户端可提交任意题目集合；`runLogId` 只记日志不参与校验。
- **静默替换**：confirm 传入的题目若部分失效，`selectByIds` 后按题库补足，可能产出与
  草案不完全一致的试卷；响应中 questionIds 反映实际结果。
- compose 会再次校验题目存在性并回填，这一致性基础可复用。

环境边界：

- 学习任务全链路当前**全部落在旧库**：用户（users，学生/管理端会话鉴权；wx 经 openid 映射）、
  题目（t_question，经 QuestionMapper 选择）、草案与工具日志（agent run log）、
  试卷/任务/答卷/错题。
- 新库（newdb，`Profile("newdb")`）现状：独立 token 鉴权（`/api/newdb/**`，与学生身份**不互通**）、
  题目导入/查询/统计。学习任务链未消费新库；试卷/答卷新库 v0 未覆盖（10.13 D-08 已预留）。

### 复用 / 适配 / 缺失清单

复用（已验证存在，保持不动）：四轮工具循环与编排器骨架；只读 `plan_practice` 与草案-确认分离；
web/wx 双 confirm 端点；事务建卷与题目再校验；个人任务派发及既有作答/回看主流程；
AgentRunRecord 留痕（plan/confirm/tool 三处）；失败降级与 SSE 流式；RAG 检索与引用事件。

适配（本 Feature 改造，方向已定）：D-08 路由四项；confirm 幂等（服务端待确认状态 + 幂等键，
重放返回同一试卷，改参数不得复用旧确认）；confirm 题目集合与草案绑定校验；
确认→作答→回看期间题目变更的一致性策略；多端功能矩阵按 D-06 另行确认。

缺失（最小新建）：服务端待确认状态与幂等确认（唯一缺失的写路径治理）；循环耗尽/预算的
显式终止事件；澄清的文本追问形态；端到端行为矩阵评测集（确定性桩与真实模型分开）；
requestId 串联路由→工具→草案→确认→paperId→作答的演示级追踪。
