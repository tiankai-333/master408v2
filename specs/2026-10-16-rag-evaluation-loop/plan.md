# Plan — RAG 检索评测与问答闭环

先收口数据与标注，再运行对照；进度见 [roadmap](../roadmap.md)。

## 任务组 1：确定一份可检查的评测输入

1. 只读确认已有语料读取、检索、引用和评测入口，列复用点；不重复实现现有引擎。
2. 选少量普通、改写、易混淆和无答案查询，展示它们的来源与人工相关性判断。
3. 定义查询身份、相关对象粒度、固定数据快照和结果记录方式，确定本轮指标与成功判据。
4. 对齐 10.13 的内容读取及后续学习任务 Feature 的引用消费边界。

出口：用户能看懂一条查询为什么应命中某条资料，数据与标注规则可用于实现；数量不以凑配额为目标。

## 后续任务组方向

- 复用检索实现，增加可重复的词法/向量/混合对照与逐条结果留存。
- 接通同一语料的回答与来源回看，验证无证据和向量不可用。
- 形成对照报告、失败分析及自我考核，供简历引用真实结果。

接口、测试命令与必要适配在任务组 1 后补齐；不先假设每个旧 API 已适配新库。
数据集可先准备，真实运行等待相应环境与费用范围明确。
