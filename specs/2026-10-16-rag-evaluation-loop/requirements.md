# Requirements — RAG 检索评测与问答闭环

## 用户结果与范围

维护者能针对一份固定语料运行可复现的检索对照，查看每条查询命中了什么、为什么失败；
学生能基于同一份语料获得可回看来源的回答，无证据时得到明确说明。

本期连接**语料 → 索引 → 检索 → 引用回答 → 逐条评测**，为知识库 Agent 提供可解释的检索依据。
不预设改动一定提升分数，不把已有回答关键词回归集当作检索黄金集。

## 最小交付

1. 语料快照说明、稳定来源身份与查询/相关性标注，可定位到具体证据。
2. 一个可重跑的检索对照入口，至少比较词法、向量、混合召回；固定模型、配置和 Top-K。
3. 逐条结果及汇总报告，说明召回覆盖、排名与延迟；保留无答案、失败和降级案例。
4. 一条从用户提问到回答及来源回看的真实问答链路，能区分无证据与向量不可用。

不新建通用评测平台，不重写检索引擎，不做大规模吞吐压测、在线调参平台或全量内容迁移。
样本与证据必须有权使用；调用成本及运行环境在实施前明确。

## 第一轮要收口的问题

- 先选哪一小份语料？题目与知识资料分别由哪个接口提供，是否已形成稳定快照？
- 标注落在题目/文档还是 chunk？不同切片方案如何比较，避免改变统计口径？
- 建议以 Recall@K、MRR 和可定位的引用核对起步；K 值、无相关答案查询的统计及通过标准待共同确定。

学习问题：检索命中和回答正确有什么区别？为什么某个查询失败？怎样证明收益来自单项改变？
