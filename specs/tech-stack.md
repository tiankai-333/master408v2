# Tech Stack — Master408 v2

本文记录当前技术事实和新增实现的默认约束。版本升级或新增基础设施必须由功能规格说明
问题、候选方案、迁移风险和验证方式；不得仅因技术流行而引入。

## 阅读口径

- **现状**：代码、依赖声明或带日期的运行记录支持的事实，不等于所有环境均验证通过。
- **约定**：新增和修改代码应满足的目标；已有实现未满足时记录差距，不伪称已经实现。
- **禁止**：本任务范围内不得实施的动作；扩展边界须先按 [变更程序](README.md#规范效力与变更) 确认。

下方“系统形态”“仓库与数据库地图”及表中当前选择为现状；约束列、一致性要求、
AI 运行时、API、测试与工程规则为约定，含否定要求的条款按禁止理解，汇总见文末
[不得采用](#不得采用)。
这些约定不是现有功能完成清单；完成证据在对应 Feature 的 validation 中。

## 系统形态

- 架构：模块化单体，前后端分离；
- 后端主应用：`apps/backend/backend-app`；
- 学生端：`apps/frontend/student`；
- 管理端：`apps/frontend/admin`；
- 第一代基线：`v1-reference`，用于兼容审计和 v1/v2 对照，不在其中继续开发新功能。

当前不主动拆微服务。只有出现独立扩缩容、故障隔离、部署边界或团队所有权需求时，才在
独立规格中评估拆分。

## 数据与状态

| 组件 | 角色 | 一致性与恢复要求 |
| --- | --- | --- |
| MySQL 8 | 业务事实、配置、评测与运行记录 | 核心事实不可由 AI 或索引反推替代 |
| Redis | 有界对话记忆和短期状态 | 用户/场景/会话隔离，必须有 TTL；不使用无界键扫描 |
| Qdrant | 向量检索索引 | 属于可重建投影，MySQL 保留文档、Chunk 与索引状态 |
| 本地静态资源/未来对象存储 | 题目图片、附件和来源材料 | 必须明确所有权、来源许可和删除生命周期 |

数据库设计必须先区分：

- 业务事实：用户、题目身份、答题、试卷等不可随意重建的数据；
- 派生状态：掌握度、画像和统计，可由事实重新计算；
- 检索投影：RAG 文档、Chunk、Embedding 和 Qdrant 索引；
- 运行记录：模型、检索、Tool、Eval 和反馈日志，主要追加写入并通过 ID 串联。

在事实源未确认前，不删除旧表或旧列，不批量增加外键，不扩大双写范围。

## AI 运行时

### 模型边界

- 使用供应商无关的模型调用边界；
- API Key 只来自环境变量或加密配置，不返回前端、不写入日志和 Git；
- 当前 Legacy/Spring 双引擎属于迁移期结构，需要能力矩阵和明确退出条件；
- Provider 切换不得要求业务 Controller 感知厂商 SDK；
- 真实调用与估算 Usage 必须明确区分。

### RAG

- 本地知识优先使用 MySQL ngram 词法召回与 Qdrant 向量召回；
- 使用带权 RRF 融合和确定性重排，改动权重前必须运行固定检索评测；
- Qdrant 不可用时保留可解释的本地词法路径；
- 回答引用必须对应实际进入回答上下文并被使用的证据；
- Chunk、Embedding、模型、参数和来源版本必须能够追踪；
- 不因已有 Hybrid Search 就默认所有请求都应检索，触发策略由专项 Eval 决定。

### Tool 与 Command

统一使用以下术语：

- **Model Tool**：真正注册给模型并可由模型选择的工具；
- **Internal Operation**：Tool 内部调用的确定性业务操作；
- **Confirmed Command**：经用户确认后由后端执行的有副作用命令；
- **Skill Configuration**：Prompt、说明和能力组合元数据，不等于可执行 Tool；
- **Trace Event**：运行记录，不代表模型真实调用。

只读 Model Tool 可以在权限与预算内自动执行。有副作用操作不得仅凭模型输出执行，必须经过
用户确认、后端授权、参数校验、幂等控制和审计。

MCP 只在跨进程复用、外部客户端接入或动态发现产生真实收益时引入；当前同进程 Tool Calling
不因缺少 MCP 而被视为技术债。

### 可靠性

- 对 429、超时、连接错误、5xx、认证错误、请求错误和本地容量拒绝分类处理；
- 只有瞬时错误允许有界重试，并尊重供应商 Retry-After；
- 流式响应首个内容 Token 发出后禁止自动重放；
- 并发、速率、步骤、时间、Token 和费用预算必须有上限；
- Tool Loop 增加后应检测 `tool name + normalized arguments` 重复调用；
- 日志失败可以不阻断只读问答，但不得静默，写操作的审计失败策略须单独规定。

## 前端基线

| 应用 | 当前选择 |
| --- | --- |
| 学生端 | Vue 3.5、Vite 6、Element Plus、Pinia、Vue Router、Axios、ECharts |

约束：

- 自由文本意图不得由前端关键词正则决定业务路由；
- 按钮和菜单可以产生显式 Command，但后端仍需验证；
- 前端隐藏操作不构成权限控制；
- AI 草案需要展示依据、参数和确认入口，不直接伪装成已执行结果；
- 历史依赖升级必须单独审计可达风险并回归登录、上传、编辑和考试主流程；
- 不在无独立需求时强行合并学生端和管理端工程。

## API 与兼容性

- 保持现有题库、考试、答题和管理接口行为，破坏性变化必须有迁移方案；
- 请求和响应结构由后端契约测试保护；
- 自然语言自动路由与显式 UI Command 在协议中明确区分；
- SSE 需要定义事件顺序、完成、错误和中断语义；
- 所有用户相关的 Memory、Task、Tool 和数据读取均绑定服务端身份；
- 对外错误返回稳定错误码和 `requestId`，不泄露密钥、SQL 或内部异常细节。

## 测试与评测

### 确定性软件测试

- 单元测试：规则、参数校验、失败分类、状态机和核心算法；
- 契约测试：数据库结构、API、Legacy/Spring 边界和迁移兼容；
- 集成测试：MySQL、Redis、Qdrant 以及关键事务和降级路径；
- 端到端测试：登录、刷题、AI 工作台、草案确认和管理操作。

### AI 评测

- 数据集必须版本化，并记录来源、标注方法和适用范围；
- 评测至少保留候选系统、基线系统、模型版本、参数、数据快照和时间；
- RAG 使用 Recall@K、MRR、nDCG、引用正确率、无结果率、延迟和成本；
- 路由使用准确率、混淆矩阵、写操作误触发率和不必要联网率；
- 生成回答区分确定性规则、人工评分和模型裁判，不把关键词出现等同于事实正确；
- 性能结果至少记录并发度、样本量、预热、P50/P95/P99、错误率和 Token 规模；
- 对复杂改造优先做消融实验，避免只比较“v1 全部旧方案”与“v2 全部新方案”。

## 工程规则

- 敏感配置不得进入仓库；
- 不提交真实用户数据和无明确再分发授权的题库、图片或解析；
- 修改数据库、权限、写操作或公开接口前必须建立功能规格与回滚方案；
- 新依赖必须说明解决的问题、备选方案、安全影响和移除成本；
- 文档中明确区分“已实现”“已验证”“设计中”“触发后再做”；
- 运行证据写入仓库文档时必须包含日期、环境、命令、样本和限制。

## 不得采用

本节汇总上文各领域约束中的禁止项，便于统一查阅；具体理由和边界条件以对应章节为准，
此处不另立结论。

- 不引入第二套运行基线或持久化栈：Python、FastAPI、LangGraph 等其他语言生态的练习
  不进入本仓库依赖与代码，相关学习在仓库外进行；
- 同进程 Tool Calling 不因缺少 MCP 视为技术债；MCP、微服务、多智能体、动态 Tool 平台
  只在[条件式扩展](roadmap.md#条件式扩展不预排期)触发条件成立后立项，不因行业热度引入；
- Skill Configuration 保持元数据定义，不升级为可执行 Tool；
- 不混入第二套 ORM；不改写已提交的 Flyway 迁移；
- 敏感配置、真实用户数据、无授权题库不入库；API Key 不返回前端、不写入日志和 Git；
- 前端隐藏操作不构成权限控制；AI 生成内容不作为业务事实；
- 流式响应首个内容 Token 发出后禁止自动重放；
- 无评测结果不宣称检索、Prompt 或模型“更好”。
