# Requirements — 新数据库与管理端落地

## 要做什么

9.20 的数据库、9.23 的管理端是设计工作。这次建立的是**执行 spec**：
把设计中真正需要的部分落成可运行的数据库与管理端，而不是再开展一轮完整架构设计。

希望得到的实际成果是：**可用的建库 SQL、实际运行的新库、能完成业务操作的新管理端**。
这是方向，不意味着第一步就建齐全部表、做完全部页面，也不预先锁死最终功能清单。

## 已明确的约定

| 编号 | 约定 |
| --- | --- |
| D-01 | 9.27 归档，不再继续它的计划，也不把其中的全部要求复制到本 Feature。9.20、9.23 的设计保留为参考，具体采用什么随执行范围确认。 |
| D-02 | 先复用现有成熟能力，确有必要才新建或改造；按业务模块推进，不要求全库一次到位，也不因新管理端而重写全部后端。 |
| D-03 | 保留新库并行、旧库不动的方向。现有线上服务和数据不得因本轮规格编写而改变；执行环境和实际操作范围在动手前明确。 |
| D-04 | 多轮交流编写：每轮只收口当前问题，逐步补需求、实施步骤和验收。只把明确接受的内容当作决定；建议与待讨论项不能写成强制任务。 |
| D-05 | 下一步执行前，应有足够清楚的范围和验证办法；后续步骤允许留白、根据结果调整，不要求开头就固定全部批次与终点。改变已确认范围时先说明影响。 |
| D-06 | 目前只编写 spec，不实施业务代码、建库或部署。等这份执行 spec 经交流写完、由用户确认本轮定稿后，再将本次归档与规格变更一次性提交；现在不提交。 |
| D-07 | 本项作为最小简历闭环的内容基础：少量题目经导入与校验进入新库，管理端能完整查看内容、来源及处理结果，后续业务通过明确接口消费同一份数据。具体首批样本、导入方式和页面范围逐轮确认，不默认恢复全部旧后台。 |
| D-08 | RAG 评测、学习任务及 NPC 包分别进入独立 Feature，不加入本项任务清单。对外提供内容读取、身份和环境边界；新库 v0 未覆盖的用户/试卷/答卷依赖，先明确复用及承担范围，不默认为应用已可直接启动。 |

## 第一步已确认并执行（2026-10-20）

经讨论确认的第一个执行切片：**少量真实题目进入本地新库，新管理端可登录、列表、详情查看**。
全程本地执行，线上服务器与旧库（本地 `master408_v2`/`xzs`、生产库）零改动。

已确认口径：

| 编号 | 决定 |
| --- | --- |
| D-09 | 新库落点：本地 MySQL（127.0.0.1:3306）同实例执行 [newdb-v0.sql](../2026-09-20-database-architecture/appendix/ddl/newdb-v0.sql)，建库名 `master408`；一次性引导，非幂等迁移。 |
| D-10 | 导入方式：Java 导入器（backend-app 内 `newdb` profile + 第二数据源 + CommandLineRunner，环境变量门控），是 D-31"唯一写入者=导入管道"的雏形；`source_ref` 唯一键幂等，重放按 duplicate 计数跳过。 |
| D-11 | 首批样本：[exam_questions.json](../../../v1-reference/crawler/data/exam_questions.json) 中 2011 年前 5 题 + 2024 年前 5 题，共 10 道单选；`score` 置 NULL（源数据无分值事实，不伪称）；`license_tag='crawler-review'`。 |
| D-12 | 管理端：新建 `apps/frontend/admin-next`（Vue 3 + Vite 6 + Element Plus，9.23 基线），登录（环境变量单账号，临时）+ 工作台 + 题目列表 + 题目详情四页；题目域只读，无编辑端点。 |
| D-13 | 旧环境零影响为硬验收：不带 profile 启动行为不变、`mvn test` 全绿、旧库行数不变、Flyway 不触碰新库。 |

`source_ref` 形如 `https://www.csgraduates.com/study_methods/408quiz/2011/#q1`：页面 URL 真实
（爬虫 config 在册），`#q{n}` 是导入器自定义约定——来源页没有题目原生锚点，此点对作者可见即可解释。
