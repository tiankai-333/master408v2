# Requirements — Hybrid RAG 与引用溯源

> 历史恢复：本文根据提交 `7744041`、Flyway V5、`RagService`、测试和工程演进记录重建。

## 背景

原线上检索仅使用 Qdrant 向量 Top-K；向量关闭或不可用时直接无结果。已有检索与引用表未接入
查询流程，无法知道候选如何产生、回答实际用了哪些证据。

## 范围

- 使用 MySQL ngram FULLTEXT 提供中文词法召回；
- 保留 Qdrant 向量召回，两路各取扩大候选集；
- 使用带权 RRF 去重融合；
- 按查询二元词覆盖和原始证据分数进行确定性重排；
- 任一路召回失败时保留另一路结果；
- 记录查询哈希、用户、策略、候选数量、分数和延迟；
- Prompt 使用编号参考，生成后仅将正文实际提到的引用标为 used。

## 非目标

- 不引入额外 Cross-Encoder 或 LLM Reranker；
- 不因 Qdrant 不可用而使本地知识检索整体失效；
- 不把返回给模型的所有候选都标记成最终引用；
- 第一版不宣称 Hybrid 一定优于单路检索，效果需要后续黄金集验证。

## 关键决策

- 候选融合采用 RRF，避免直接比较不可校准的向量和全文分数；
- 重排保持本地确定性，以获得低成本和可复现行为；
- 检索日志与回答引用分开：前者记录候选过程，后者记录最终使用；
- MySQL 是正文和 Chunk 状态的可追踪来源，Qdrant 是可重建索引。

## 完成定义

检索能够融合向量和词法候选，在单路故障时降级，并为每次回答保留候选产生过程和正文实际
使用的来源；现阶段完成定义不包含“质量显著提升”的结论。
