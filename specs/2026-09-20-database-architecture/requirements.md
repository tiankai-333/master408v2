## 目标与范围

为管理端重建和后续 RAG 评测建立明确的题目数据契约。第一批对象是题目领域，覆盖
`t_question`、`t_text_content`、`question_content`、`question_source`、`question_asset`、
`question_knowledge_point`，并追踪考试、答题、知识图谱和 RAG 的依赖。

本 Feature 交付四件东西：事实审计报告、字段所有权与版本契约、生命周期与物理结构设计、
迁移与回滚方案。迁移实施另有独立验收，不在本轮完成条件内。

全库其他领域只记录依赖，不在本轮同时重构身份、PromptOps、学习画像和 AI 日志。

## 已核对的现状

### 本次完善的设计重点

本 Feature 解决特殊格式题目的逻辑模型与数据契约，不以复刻旧管理端、旧 API 或现有表结构为目标。
旧系统审计用于识别需要保护的数据与引用，不要求作者先背诵旧调用链。
展示与 RAG 的需求分别设计：前者保留题意与排版，后者提供可检索且可追溯的表示；
不得让两套内容独立修改后失去对应关系。具体权威格式及物理表结构仍需样本验证后决定。

以 [复杂题目样本契约](appendix/sample-contract.md) 中的 2024 年 408 第 43 题为核心，
第 1 题为简单代码对照。此前误发的“劳动的本质、分类及作用”不作为样本或依据。

保留现有 Hybrid RAG：MySQL 文档/Chunk、Qdrant 向量、词法与向量融合及引用链路。
本轮重点设计输入与版本关联，不重写检索引擎，不引入新 OCR、多模态服务或新的存储基础设施。
已有实现不等于复杂图题质量已验证，参见 [历史 RAG 验证](../2026-07-27-hybrid-rag/validation.md)。

### 静态基线

来源：[数据库事实源清单](../../docs/数据库事实源清单.md)、Flyway
[`V1__baseline.sql`](../../apps/backend/backend-app/src/main/resources/db/migration/V1__baseline.sql)，
以及下列代码入口。静态结论一律标注为「待运行验证」，不当作已验证事实。

- 标准新增/编辑在事务中写题目、旧 JSON 和新版内容。
- 题干和解析可以被新版内容覆盖；选项仍读旧 JSON，答案按题型从不同位置读取。
- `question_content` 对 `(question_id, version)` 有唯一约束，对 current 只有普通索引
  `idx_question_content_current`；查询按版本倒序取一条，不能据此证明 current 唯一。
- 新版本号通过 `SELECT COALESCE(MAX(version), 0) + 1` 产生，随后 `clearCurrent` 再 `insert`；
  并发编辑的冲突处理尚未验证。
- 旧内容编辑为原记录更新；试卷读取调用当前题目读取，部分判分读取 `Question.correct`。
  历史题面与答案是否稳定尚未得到验证。
- 回填从扩展列取 options，标准编辑从 items 序列化；两条路径的数据表示和 hash 算法不同
  （见 `QuestionContentMapper.xml` 的 `backfillFromLegacy` 与 `saveFromEdit`），
  不能直接比较现有 `source_hash` 来判断新旧语义一致。

## 范围

包含：

- 题目领域的六张表及其内容版本契约；
- 字段级权威写入者、兼容副本和派生值的划分；
- 历史考试与 RAG 投影的版本绑定规则；
- 迁移、对账、回滚的可执行方案（设计层），并在隔离库演练候选 DDL。

不包含：正式迁移与数据回填、删除任何表或列、切换线上读路径、为其他领域（身份、PromptOps、
学习画像、AI 日志）重新设计结构、以及管理端页面实现。

## 已确认决策

以下是本轮已经定下的设计立场。每条都写明依据，实施时如需推翻必须回到本表更新。

| 编号 | 决策 | 依据 |
| --- | --- | --- |
| D-01 | `t_question` 收敛为题目身份与业务属性聚合根；其重复内容列进入只读兼容，不立即删除 | 事实源清单 4.1：`t_question` 不能从其他表重建，物理删除会破坏试卷与答题引用 |
| D-02 | `question_content` 收敛为题干、选项、答案、解析及版本历史的权威载体 | 事实源清单 4.3；`QuestionContentMapper.xml` 已有版本、`is_current`、`source_hash` 结构 |
| D-03 | `t_text_content` 的退出按引用它的业务类型分别判断，题目内容迁移完成不等于整表可删 | 事实源清单 4.2：试卷 Frame、答题文本和任务内容共用该表 |
| D-04 | `question_source`、`question_asset`、`question_knowledge_point` 暂不接入主链，也不删除；先由审计决定它们是独有事实还是可重建投影 | 事实源清单 4.4-4.6；DB-TD-Q04 记录维护闭环缺失 |
| D-05 | 历史考试的内容绑定在业务时点固定，不依赖数据库隔离级别的读取视图 | 事务视图只覆盖单次事务；历史留存的周期远长于任何事务 |
| D-06 | 旧数据无法恢复当时的题目版本时，显式标记为不可恢复，不用当前版本补齐历史 | DB-06；避免把现在的答案伪装成过去的答案 |
| D-07 | 不因本 Feature 批量补外键；先完成孤儿与重复检查，再按收益单独论证 | DB-TD-Q05；六张表当前全靠应用约定，补外键会改变现有写入行为 |
| D-08 | RAG 文档、切片与向量整体定性为可重建投影，必须携带源版本与生成配置 | DB-09；现有 hash 仅为对照线索，不证明完整版本和生成配置已落库 |
| D-09 | current 唯一性必须有数据库级保障，不能只靠应用层先清后插 | `idx_question_content_current` 是普通索引；完整事务中已有主表更新的锁影响仍须复现，不能断言整个调用链无互斥。候选 DDL 见 `ddl/` |
| D-10 | 写入幂等按「请求身份」与「业务身份」分别定义；`SELECT MAX(version) + 1` 的竞态靠唯一键暴露而非静默重试 | DB-05、DB-10；重复请求与合法二次编辑必须可区分 |
| D-11 | 阈值（一致率、成功率、覆盖率）一律由审计基线推导，不在设计文档中预设数字 | 与 validation 完成门槛一致；避免编造迁移成功率 |
| D-12 | 设计验收在隔离库执行，共享开发库只跑只读审计 | `audit-queries.sql` 全部为 SELECT；写探针只在演练库执行 |
| D-13 | current 唯一性采用**生成列 + 唯一索引**（候选 A，`ddl/current-uniqueness-strict.sql`） | Q-01 拍板：T1-3/T1-5 实测 A、B 均可行，选 A 因为直观、便于查看与维护；多一列的成本可接受。候选 B（函数索引）记录为备选 |
| D-14 | 数据库只保证「**至多一个 current**」；「可用题目必须有一个 current」由事务与业务校验保证 | Q-01 拍板：T1-4 证明唯一键不保证存在性。保存失败必须整体回滚；进入考试时找不到可用版本必须拒绝并明确报错；巡检只用于发现异常，不替代写入时的保证 |
| D-15 | 并发编辑一律**拒绝并要求刷新**，且必须**保留用户未保存的输入**；不自动合并答案与解析，不静默覆盖 | Q-02 拍板：T2-2 实测竞争失败为显式 1062，可被翻译为业务冲突提示 |
| D-16 | 提交编辑时携带「打开编辑页时的版本号」；即使未触发唯一键冲突，只要该题已被他人更新也必须提示冲突 | Q-02 拍板：唯一键只解决版本重号，不足以防止旧页面覆盖新内容（乐观并发校验） |
| D-17 | 历史作答在**开始作答时绑定不可变题目版本**；展示题面、自动判分与历史回看统一使用该版本；交卷只保存答案与结果，不重新选择版本 | Q-03 拍板 + 走查结论：现状在交卷时绑定**可变**的 `t_text_content` 行（`ExamPaperAnswerServiceImpl:212` + `QuestionServiceImpl:120-122`），换任何时点都无法冻结历史；`question_content` 的追加式版本行才可冻结。「试卷发布时固定版本」留待将来"全场同卷"需求 |
| D-18 | 管理端**展示来源**（来源名称、年份、题号、原始引用等）；缺失字段显式为空，不推测补齐；原始采集信息保留，人工修改另留记录 | Q-04 拍板：A-08 证明 `raw_ref`/`metadata` 100% 覆盖且不可派生，来源不能是只存不看的数据；完整来源管理平台不在本期 |
| D-19 | **图片与外部 HTML 的资源契约在本期范围内**：明确文件归属（题目版本、题干或解析）、定位与校验与备份方式、缺失时的标记、以及"更新文件不得改变历史版本的题面"；素材库、批量上传后台、OCR 平台、强制对象存储不在本期 | Q-05 拍板：复杂题面依赖仓库外的 `question-html/**`（13318 文件 / 159 MB / 被 gitignore），不能因 `question_asset` 为空而忽略 |
| D-20 | 允许管理员**添加/移除题目与知识点的关联**并记录修改人与时间；区分人工标注与自动生成，**自动任务不得无声覆盖人工结果**；当前 643 条孤儿关系先隔离并查明原因，不凭题意猜测对应关系 | Q-06 拍板：需要人工纠错能力，但不需要多级审核流程 |
| D-21 | 软删除统一称为「**停用**」：阻止新组卷与新增入卷；已组卷未开始者保留引用并提示、阻止新的作答启动、要求管理员替换或确认；已开始的作答继续使用已固定版本、不中途换题；已完成考试与历史答卷保持可读且不改评分；错题本保留历史并标记停用、不进入新练习推荐；RAG 不再作为新检索证据，返回前过滤；历史 AI 回答不改写，引用可标记题目已停用 | Q-07 拍板（逐场景行为见表下 Q-07 卡片）。因版权或安全的**紧急撤下**是另一种操作，不与停用混用 |
| D-22 | 题型编号**统一采用后端与学生端定义：3=判断、4=填空**；管理端编号为偏差方，本轮只写入规格与后续修复任务，**不直接修改前端** | Q-13 拍板。依据：管理端 `list.vue:97-98`、`gap-filling.vue:55`（提交 3）、`true-false.vue:53`（提交 4）与后端 `QuestionTypeEnum:10-11` 相反，学生端与后端一致。当前审计未发现 3/4 两类数据，但**不等于永久零迁移风险**：实施前必须再次检查是否已产生该类数据，并补齐五题型契约测试 |
| D-23 | 权威内容格式采用**结构化内容块**：一题拆为有稳定标识与顺序的块（题干 / 公共材料 / 小问 1..n / 答案 / 解析）；**块内原文保留 HTML（或 Markdown）不过度解析**，纯文本投影（`*_text`）按规则从块重新生成；拆不出的旧题保留"单块整段"降级表示。块的物理落库形态（JSON schema、块表，或复用 `t_essay_question`）在物理结构附录定稿（回应 U-10、U-11） | Q-09 拍板（2026-09-23，推荐方案整体确认）。依据：样本 2024/43 证明多图+公共材料+多小问必须**块级定位**（DB-12：引用、检索、资源关联、"解析资源不得混入题面"都需要块身份）；现状整段 HTML+外链 div 无法表达"这一问用哪张图"、小问顺序不稳定 |
| D-24 | 版本模型采用**简化版本 + 显式发布标记**，不做完整草稿工作流：保存即产生新版本且仅一个 current（现有机制保留）；增加"已发布"标记表达"该版本曾对外使用"；历史绑定（D-17）绑**具体版本行**，与是否发布无关 | Q-10 拍板（2026-09-23）。D-17 的不可变版本已解决历史一致性，完整草稿流程是第二套状态与权限、收益有限。代价已接受：无法表达"正在编辑、暂不可见"；将来需审校/多级发布再按 D-20 留痕模式补状态字段 |
| D-25 | RAG 就绪度拆为**展示就绪与检索就绪两个独立状态**并分级降级：展示未就绪（缺图/缺内容）只返回原题+明确"资料未就绪"提示、**不进入自动解答**；展示就绪但检索未就绪时，自动解答**只用词法召回**（`rag_chunk.content_text`）并标注"向量检索未就绪"；已停用不作为新检索证据（D-21） | Q-11 拍板（2026-09-23）。DB-14 要求失败或缺失不得标为完整成功；现状 `rag_document.status='ready'` 混同两种含义（2839 个题目文档缺向量索引即为例证）。检索路径需加状态判断，并把"向量未就绪"与"无可用证据"区分，避免降级被误读为"模型答不出" |
| D-26 | 资源以**引用 + 校验值 + 归属**记录：归属（题目版本 id、块 id、题干或解析）、定位（相对路径/URL）、校验值（内容 hash 或大小+修改时间）、可得性（存在/缺失/不可用）；派生结果记录源题目版本、源块、生成规则版本、模型与集合、校验状态；**不强制迁入对象存储**。落库形态（启用 `question_asset` 补版本/块归属列，或另建资源引用表）在物理结构附录二选一定稿——无论哪种，都必须能回答"这个文件属于哪一版、哪一块" | Q-12 拍板（2026-09-23）。D-19（资源契约纳本期）+ D-08（投影带源版本）。资源写入者目前为零（TD-016），外部文件受授权限制仍在仓库之外（TD-015），"可得性"只表达状态、不解决保管 |
| D-27 | `t_text_content` 题目部分**分字段退役、整表保留**：在 `migration-plan.md` 第 0.1 节 R-1～R-4 全部满足后按字段退出（先停写、再切读、再确认无其他业务依赖、再观察一个窗口）；退出顺序：`t_question` 重复内容列（读侧本已不可达）→ `t_text_content` 题目部分读取 → 最后停止写入 | Q-08 拍板（2026-09-23）。D-03：该表被试卷 Frame、答题文本和任务内容共用，删表波及其他领域；D-01 的"重复内容列只读兼容"给了先后顺序。长期需维护"哪些字段已退役、哪些仍使用"清单（放 `data-contract.md` 字段表） |
| D-28 | 简答题 `correct_answer` **允许为空且不自动补齐**：空值作为合法状态写入契约（与 D-06"不可恢复显式标记、不伪造历史"一致）；成因（业务无标准答案 vs 导入漏采）在实施前由内容负责人最终确认，再决定是否安排补采流程 | 待验证 #8 作者确认（2026-09-23，先按"允许为空且不补齐"）。影响 DB-03：五题型契约中简答题的答案语义必须显式声明可空，不得把空值当异常 |

## 边界与影响

- 本轮不直接删除表、覆盖历史、执行回填或切换线上读路径。
- 最终表名、外键和存储格式在审计与方案比较后确定。
- 现有能力缺少运行证据的地方一律保持「待验证」，不用推断补齐。
- 任何 DDL 在共享库执行前必须先在本 Feature 之外确认发布顺序、兼容窗口和回滚动作。

## 学习目标与完整问题

来源分为两类，分别标注，不把项目自拟题包装成有面经来源的高频题。

**A. 项目自拟（对应 validation 的自我考核）**

- 同一道题的题干、选项和答案目前分别从哪里读取？目标设计如何保证它们属于同一版本？
- 两个管理员同时编辑一道题时，事务和唯一约束分别能保障什么？剩下的竞态由谁处理？
- 题库答案修改后，已完成考试应该展示哪个答案？如何证明历史记录一致？
- 内容更新成功但向量索引更新失败时，系统处于什么状态？如何发现并恢复？

**B. 面经改编（来源、时间不确定性与完整题目清单见 [validation.md](validation.md#面经改编模拟题)）**

- 数据库乐观锁与悲观锁的实现与代价；
- 接口幂等：如何识别同一个请求；
- Spring Boot 事务边界与故障回滚；
- 全量转增量同步的漏数与删除处理；
- 数据库与派生索引的一致性维护。

B 类只作为学习方向，来源标注为公开面经转述，不声称频率或官方性。
