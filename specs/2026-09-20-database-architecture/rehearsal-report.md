### 3.1 被跳过题目的闭环（必须有，不允许"跳过了就算"）

| 环节 | 内容 |
| --- | --- |
| **原因** | 缺 `version=1` 但已有 `is_current=1` 的行；直接回填会撞 `uk_question_content_current` 并使**整个批次**失败（见第 4 节） |
| **记录** | 题目 id、形态、发现批次、发现时间、判定依据，写入迁移记录的"跳过清单" |
| **处理责任** | **未指定**——需要业务决策（补一个 v1 并决定它与既有 current 的关系？还是承认该题只有 v2？），本 Feature 不做此决策 |
| **重试方式** | 人工处理完成后，把该题从跳过清单移除并重跑其所属批次；脚本按清单过滤，重跑保持幂等 |
| **最终去向** | 按三态口径（已证实 / 候选匹配、未证实 / 不可恢复）由人工归类；**在归类完成前保持"跳过"状态**，不得自动补齐、不得自动绑定 |

> 本次演练只证明了"跳过清单能被前置普查产出"，**没有**验证闭环的后半段
> （人工处理 → 重新入批 → 最终归类），因为那需要业务决策参与。

## 4. 故障注入（关键证据）

**不做前置普查、直接回填陷阱题**：

```
ERROR 1062 (23000): Duplicate entry '910020' for key 'question_content.uk_question_content_current'
失败后该题内容行数 = 1     ← 语句整体被拒绝，没有半插入
```

结论（**严格限定在该语句上**）：

1. 候选 A 的唯一键**真的会拦住**"缺 v1 但已有 current"的回填（与 T4-3 的推断一致）；
2. **该条 INSERT ... SELECT 语句没有留下部分写入**——失败后该题内容行数仍为 1；
3. 但这也意味着：**批次内只要有一条这样的题目，整个批次都会失败**。
   所以迁移**必须先普查并跳过**，不能依赖唯一键报错来发现。

> **不得扩大**：第 2 条只支持"这一条语句是原子的、未产生半插入"。
> 它**不能**推广为"整个迁移流程都能正确回滚"——多语句事务、批次记录写入、跨阶段的中断恢复、
> 读路径切换的回退，都**没有**在本次演练中被验证。第 5 节列出本演练覆盖不到的项。

**尚未验证的一点（重要）**：`migration-plan.md` 写的"单题失败只回滚该题（逐题事务或子事务）"
**在本次演练中没有被验证**——演练用的是整批语句，观察到的是整批失败。
实施阶段若采用逐题隔离，必须另做一次演练证明"坏题不影响同批其他题"。

## 5. 演练验证了什么、没验证什么

**已验证**（仅限本次样本与本组语句）：

- 分批执行可行；批次边界用主键区间即可表达；
- 在这组样本上，重复执行同一批次不新增行（`NOT EXISTS (version = 1)` 生效）；
- 在本演练模拟的"整段重跑"方式下，从中断点重跑不产生重复行；
- 软删除题不参与回填；
- 陷阱题可由**一条前置普查查询**发现，也可由连续性对账发现；
- 对账查询（覆盖率、current 分桶、版本连续性、软删除泄漏、孤儿关系）都能产出可核对的数字；
- 候选 A 的唯一键在该回填语句上生效，且**该语句**失败时不留下部分写入。

**未验证**：

- **逐题异常隔离**（第 4 节）：本演练用的是整批语句，观察到的是整批失败；
- **中断恢复的其余场景**：部分提交后崩溃、连接中断、锁等待超时、批次记录损坏、并发迁移；
- **多语句事务与批次记录的回滚**：未验证"整个迁移流程可回滚"；
- 全量规模的表现（本 Feature 不做全量演练）；
- 读路径切换与双写观察（阶段 4/5）；
- 旧结构退役的具体步骤与备份/回滚窗口（本次只写进目标，未演练）；
- 第 43 题相关的内容转换规则（依赖样本核对，仍是草案）。
