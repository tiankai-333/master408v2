## Q-01 current 唯一性用哪条路径

| 候选 | 做法 | 实测 | 代价 |
| --- | --- | --- | --- |
| **A** | 生成列 `current_question_id` + 唯一键 | T1-3 通过：能拒绝第二个 current | 加一列；影响 `SELECT *`、模型映射、备份/迁移脚本都要带上 |
| **B** | 函数唯一索引 `((IF(is_current=b'1', question_id, NULL)))` | T1-5 通过：能力等同 A | 不加列；依赖 MySQL ≥ 8.0.13；表达式索引的解释计划与跨版本降级更难 |

建议：**候选 B + 独立的存在性巡检**（零列变更、迁移面最小）；若更看重可解释性与工具兼容性则选 A。

## Q-02 并发编辑的冲突响应语义

候选：① 拒绝并要求刷新后重试；② 自动合并；③ 自动重试产生新版本。

证据：T2-2 实测——两个线程同时编辑，成功方写入 v2，失败方得到**显式 1062**
（`Duplicate entry '990301-2' for key 'uk_question_content_version'`），最终 current 恒为 1 行；
T2-3 证明失败后不会留下 0 个 current 的半成品。

代价：① 语义最清晰、可审计，但用户要重做编辑；③ 会让"谁改的、改了哪一版"变得不可追溯，
且与 D-10 要求的「重复请求与合法二次编辑必须可区分」冲突。

建议：**① 拒绝**，服务层把 `DuplicateKeyException` 翻译为业务错误（"该题已被他人更新，请刷新后重试"），
不要返回 500。

> **需要你确认**：接受"拒绝并要求刷新"吗？（这决定管理端的编辑交互成本）

## Q-03 历史考试的内容绑定时机

候选：组卷时固定 / 开始答题时固定 / 交卷时固定（或完整快照）。

**走查结果（2026-09-21，已完成三处写入点核对）**：

| 事实 | 证据 |
| --- | --- |
| 现有绑定发生在**交卷时**（不是组卷或开始答题） | `ExamPaperAnswerServiceImpl:202` 的方法注释为"用户提交答案的转化存储对象"，`:212` 在此写入 `questionTextContentId` |
| 绑定的是 `t_question.info_text_content_id`（旧表示的行 id） | `ExamPaperAnswerServiceImpl:212` |
| **该行是可变的**：题目编辑走的是就地更新同一行 | `QuestionServiceImpl:120-122`（`selectById` → `setQuestionInfoFromVM` → `updateByIdFilter`） |
| 判分同样读"当前位置"的答案 | `ExamPaperAnswerServiceImpl:234`（单选/判断用 `question.getCorrect()` 比对） |
| 因此**换哪个时点都冻不住历史**：绑定的行本身会被改写 | 由上三条推出 |

对比：`question_content` 的版本行是**追加式**的——`saveFromEdit` 每次都插入新版本、只翻转
`is_current` 标志（`QuestionContentServiceImpl:53-54`），`backfillFromLegacy` 也只在缺 `version=1` 时插入。
所以**只有绑到版本行才真正冻结历史**。

代价对比：

- 继续绑 `t_text_content.id`：实现零改动，但历史题面与判分依据会随题库编辑而改变（D-06 的"伪装成过去的答案"）；
- 绑 `question_content.id` / `(question_id, version)`：历史真正稳定，但需要回填历史记录、并处理
  "交卷时该题还没有任何内容版本"的边界（真实数据中 6613/6613 都有 version=1，风险有限）；
- 完整快照（把题面复制进答题记录）：最稳，存储放大，且要定义快照格式。

建议：**绑定到不可变版本行**（`question_content.id`），而不是继续绑可变行；时点维持"交卷时"，
但把它写进契约并补一条交卷时"必须存在可用版本"的校验（当前无此校验）。

> **需要你确认**：是否接受"交卷时绑到 `question_content` 版本行"这一方向？
> 若你更希望组卷时就固定，我需要再走查组卷侧是否有落库点（目前未见）。
