## 0. 推荐方案的一句话概括

**内容结构化、版本不可变、资源与内容分离、检索有降级表达、旧结构分字段退役。**

这五条互相咬合：结构化内容块（Q-09）是多图多小问的前提；块与版本绑定（已有 D-17）使历史可回放；
资源按"引用 + 校验 + 归属"记录（Q-12）才能既保真又不把授权受限的文件塞进数据库；
"展示就绪/检索就绪"分开（Q-11）才不会把 RAG 未完成误报成完整成功；旧结构按字段退役（Q-08）
才能结束"双份内容"，而不是永久并存。

## Q-09 权威内容格式与层次

**推荐：结构化内容块**——把一题拆成有稳定标识与顺序的块：`题干` / `公共材料` / `小问 1..n` /
`答案` / `解析`；**块内原文保留 HTML（或 Markdown）不过度解析**，纯文本投影按规则另行生成。

理由：

- 第 43 题这类"多图 + 公共材料 + 多小问 + 答案解析"必须能**分别定位**某一块：引用、检索、
  资源关联、以及"解析资源不得混入作答题面"（DB-12）都需要块级身份；
- 现状用整段 HTML + 外链 div，无法表达"这一问用哪张图"，也无法保证小问顺序稳定；
- 块内保留原样 HTML 可以同时满足"保真"与"可投影"（DB-04）。

代价：

- 需要块级结构（JSON schema 或块表）+ 转换器；编辑界面要支持按块编辑（工作量在实施阶段）；
- 现有 6613 题的题干是"整段 + 外链"，转换需要规则化拆分；对拆不出来的题必须保留"单块整段"的降级表示。

## Q-10 草稿与发布是否分离

**推荐：简化版本 + 显式发布标记**，不做完整草稿工作流。

- 保存即产生新版本，且只有一个 `current`（现有机制保留）；
- 增加一个"已发布"标记（或状态字段），用于表达"这个版本曾经对外使用过"；
- 历史绑定（D-17）绑的是**具体版本行**，与是否发布无关，因此不需要草稿态来保证历史。

理由：D-17 已经用"不可变版本 + 展示/判分/回看统一按绑定版本"解决了历史一致性问题；
再引入完整草稿流程会增加第二套状态与权限，收益有限。

代价：无法表达"正在编辑、暂不可见"；若将来需要审校/多级发布，再补状态字段（届时按 D-20 的留痕模式补）。

## Q-11 RAG 未完成时的使用规则

**推荐：把"展示就绪"与"检索就绪"拆成两个独立状态，并分级降级。**

| 状态组合 | 行为 |
| --- | --- |
| 展示就绪 + 检索就绪 | 正常：展示原题 + 自动解答引用检索证据 |
| 展示就绪 + **检索未就绪** | 展示原题与降级文本；自动解答**只用词法召回**（`rag_chunk.content_text`），并标注"向量检索未就绪" |
| **展示未就绪**（缺图/缺内容） | 只返回原题 + 明确的"资料未就绪"提示；**不进入自动解答**，避免用残缺材料生成答案 |
| 已停用 | 不作为新检索证据；返回前过滤（D-21） |

理由：DB-14 要求"展示可用与检索/解答可用分别表达，失败或缺失不得被标为完整成功"；
现状 `rag_document.status='ready'` 把两种含义混在一起（2839 个题目文档缺向量索引即为例证）；
且不得把"缺向量索引"说成"完全不可检索"。

代价：检索路径要加状态判断与提示文案；需要把"向量未就绪"与"无可用证据"两种情况区分开，
避免降级被误读为"模型答不出"。

## Q-12 资源与派生结果的存储映射

**推荐：资源以"引用 + 校验值 + 归属"记录；派生结果带源版本与生成配置。不强制迁入对象存储。**

- 资源（外部 HTML、图片、附件）记录：**归属**（题目版本 id、块 id、题干或解析）、**定位**（相对路径/URL）、
  **校验值**（内容 hash 或大小 + 修改时间）、**可得性**（存在/缺失/不可用）；
- 派生结果（RAG 文档/切片/向量）记录：源题目版本、源块、生成规则版本、模型与集合、校验状态；
- 落库形态候选：**启用 `question_asset` 并补版本/块归属列**（现在的表结构已接近，缺的是归属与校验字段与写入者），
  或另建一张"资源引用表"。二选一，不在本期决定——但无论哪种，都必须能回答"这个文件属于哪一版、哪一块"。

理由：D-19 要求"文件属于哪个题目版本、题干还是解析；如何定位、校验与备份；缺失时如何标记；
更新文件不能改变历史版本的题面"；D-08 要求投影可重建并带源版本。而 D-19 已排除素材后台与对象存储。

代价：需要资源写入者（目前零写入者，见 TD-016）；外部文件仍在仓库之外且受授权限制（TD-015），
"可得性"字段只能表达状态，不能解决文件本身的保管问题。

## Q-08 `t_text_content` 题目部分何时退出

**推荐：分字段退役，`t_text_content` 表保留。**

- 题目部分（题干/解析/选项所依赖的内容）在 `migration-plan.md` 第 0.1 节的 **R-1～R-4 全部满足后按字段退出**：
  先停写、再切读、再确认无其他业务依赖、再观察一个窗口；
- **整表不删除**：它同时被试卷 Frame、答题文本和任务内容共用（D-03），删表会波及其他领域；
- 退出顺序建议：`t_question` 的重复内容列（读侧本已不可达）→ `t_text_content` 的题目部分读取 →
  最后停止写入。

理由：D-03 明确"题目内容迁移完成不等于整表可删"，而 D-01 的"重复内容列进入只读兼容"给了先后顺序。

代价：长期保留一张多用途表；需要维护"哪些字段已退役、哪些仍在使用"的清单（放在 `data-contract.md` 字段表中）。
