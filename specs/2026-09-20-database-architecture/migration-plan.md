## 0.1 最终目标（必须包含旧结构退役）

> **双份内容不是目标状态。** 迁移的最终目标是从"混合事实源"收敛到单一权威表示，
> 并把旧结构退役；期间的双写只是过渡手段，必须有明确的退出条件。

退役必须逐项写清下列五件事，缺一不可：

| # | 项 | 要求 |
| --- | --- | --- |
| R-1 | **停止旧写入** | 关闭所有向 `t_text_content`（题目部分）与 `t_question` 重复内容列的写入路径；按 `entry-inventory.md` 的写入口清单逐一核对，期间观察一个完整周期无新增写入 |
| R-2 | **切换读取** | 展示、判分、历史回看、RAG 投影全部改读权威表示；旧路径保留为只读兼容，且必须有回退开关 |
| R-3 | **解除其他业务依赖** | `t_text_content` 还被试卷 Frame、答题文本、任务内容共用（D-03）——必须逐业务类型确认不再依赖题目部分，**不能因为"题目迁移完成"就整表删除** |
| R-4 | **备份与回滚窗口** | 退役前完成全量备份并验证可恢复；定义观察期长度与回滚触发条件；窗口内旧结构只读保留、不删 |
| R-5 | **满足条件后删除旧列或旧表** | 仅当 R-1～R-4 全部满足、且观察期内无回退，才执行删除；删除动作本身要有独立回滚方案（从备份恢复） |

**当前状态**：R-1～R-5 的具体时机受 **Q-08**（`t_text_content` 题目部分何时退出）阻塞，

## 1. 分阶段迁移（每阶段都有退出条件与回滚动作）

### 阶段 0：准备与冻结

- 目标：让迁移可重复、可对账、可中断。
- 动作：固定代码提交与结构版本（Flyway V5）；导出前后结构快照；建立批次表与断点记录；
  确认所有写入入口（`entry-inventory.md`）在迁移窗口内的开关与降级行为。
- 校验：结构快照与 `information_schema` 一致；对账脚本可在空库上跑通（不写数据）。
- 退出条件：`audit-report.md` 的基线可重跑且数字一致。
- 回滚：无需（只读）。

### 阶段 1：扩展结构（只加列/索引，不改语义）

- 动作（对应 `physical-design.md`）：
  1. `question_content.current_question_id` + `uk_question_content_current`（候选 A，D-13）；
  2. `t_exam_paper_question_customer_answer.question_content_id`（D-17 锚点，先只建列，不写）；
  3. `question_knowledge_point.source/update_user/update_time`（D-20）；
  4. `t_question.status_reason/status_update_user/status_update_time`（D-21）。
- 前置校验：A-03 的 `multiple_current = 0`（已有数据不允许违反新唯一键）；否则先处理多 current 再建约束。
- 退出条件：DDL 全部成功；**旧代码仍可运行**（新列均可空或带默认值）；读路径未切换。
- 回滚：按 `physical-design.md` 第 9 节的逆序删索引/删列。

### 阶段 2：内容转换与回填

- 动作：按 `data-contract.md` 的字段所有权，把仍缺权威来源的内容补齐到 `question_content`；
  回填语句保持 `NOT EXISTS (version = 1)` 的幂等口径（T4-1/T4-2 已验证）。
- **已知陷阱（T4-3）**：对"缺 `version=1` 但已有 current 行"的题目，现有回填会**造出第二个 current**。
  迁移前必须先跑一遍该形态的普查（当前真实数据为 0，但必须每次执行前复查），
  并约定：这类题目**跳过回填并登记为待人工处理**，不依赖唯一键报错来发现。
- 幂等键：`(question_id, version=1)`；重复执行不新增行、`source_hash` 不变（T4-2）。
- 退出条件：回填前后 `question_content` 行数、版本分布、`source_hash` 抽样一致；异常题目有清单。
- 回滚：删除本次回填产生的 `version=1` 行（按 `create_time` 与批次标识限定），不影响既有版本。

### 阶段 3：对账

- 动作：按第 8 节的报告格式输出四类对账：覆盖率、唯一 current、版本连续性、内容一致率；
  逐条给出 A 编号与 SQL 原文；冲突样本**隔离并保留原值**，不猜测修复。
- 退出条件：对账数字可由脚本复现；失败样本可定位到具体题目并有人工处理结论。
- 回滚：无需（只读）。

### 阶段 4：读路径切换

- 动作：按批次切换读取来源——先切"当前版本"读取（可用候选 A 的列，`physical-design.md` 第 3 节），
  再切 D-17 的"按绑定版本读取"（仅对新作答生效）。
- 前置：写入路径已先按新契约发布（否则会出现新的"只写不读"字段——`data-contract.md` 已记录该现状）。
- 退出条件：新旧读法在同一批样本上返回一致结果（差异逐条登记）；监控无异常。
- 回滚：读法开关切回旧路径；阶段 1 的新列保留（不影响旧代码）。

### 阶段 5：旧写入退出

- 动作：停止向旧表示写入（`t_text_content` 的题目部分、`t_question` 的重复内容列），
  仅保留只读兼容；**何时退出取决于 Q-08**。
- 退出条件：所有写入入口清单核对完毕；旧表示无新增写入（按 `create_time` 观察一个完整周期）。
- 回滚：恢复旧写入开关；旧表示在此期间未被删除，因此可回退。

## 2. 批次、幂等、断点与异常隔离（DB-10）

| 项 | 设计 |
| --- | --- |
| 批次 | 按 `question_id` 区间分批（建议每批 500–1000 题），批次号写入迁移记录表 |
| 幂等键 | 内容回填：`(question_id, version=1)`；绑定：`(作答实例 id, question_id)` |
| 断点 | 记录"最后成功批次 + 最后处理的主键"；重跑从断点继续，不用时间去猜 |
| 异常隔离 | 单题失败只回滚该题（逐题事务或子事务），不整批回滚；失败题目进隔离清单 |
| 校验报告 | 每批输出"处理数/成功/跳过/失败/异常原因"，可累加对账 |

## 3. 版本绑定映射表（候选方向，须同时定义四件事）

> 用户要求：映射表方向可作为候选，但必须同时定义**作答实例、开始操作幂等、恢复作答、交卷如何引用同一实例**。
> 以下为设计草案，实施阶段确认。

- **作答实例**：一次"开始作答"生成一个不可变 `attempt_id`（现有 `t_exam_paper_answer` 实例可作为承载，
  或新增实例表）。**版本绑定挂在实例上，不挂在题目上**。
- **开始操作幂等**：以 `(user_id, exam_paper_id, attempt_seq)` 或客户端提交的 `start_request_id` 作为幂等键；
  重复的"开始"请求返回**同一个实例**，不重复生成绑定。
- **恢复作答**：按实例 id 恢复，**沿用该实例已有的绑定**；不得因为恢复而重新选择版本
  （否则等于中途换题，违反 D-21 对"已开始作答"的规定）。
- **交卷**：交卷只写答案与结果，**按实例 id 引用绑定映射**；不得在交卷时重新解析当前版本
  （现状 `ExamPaperAnswerServiceImpl:212` 正是这样做的，必须一并改）。
- **绑定对象**：`question_content.id`（追加式版本行）。绑定后不再变更。
- **失败行为**：开始作答时找不到可用版本 → 拒绝开始并明确报错（D-14）；恢复作答时发现绑定行缺失或不可读
  → 报错并保留实例，不静默回退到当前版本。
- **表结构候选**（实施阶段定稿，不在本 Feature 执行）：

```sql
-- 候选：作答实例 → 题目 → 绑定的内容版本
CREATE TABLE exam_paper_answer_question_binding (
  id INT NOT NULL AUTO_INCREMENT,
  attempt_id INT NOT NULL,
  question_id INT NOT NULL,
  question_content_id INT NOT NULL,
  bound_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_attempt_question (attempt_id, question_id),   -- 幂等键
  KEY idx_binding_content (question_content_id)
);
```

## 4. 历史答卷：只登记候选，不执行绑定

**三态口径**（`physical-design.md` 第 8 节）：已证实 / 候选匹配、未证实 / 不可恢复。

- **108 条全部归入「候选匹配、未证实」**。依据只说明"当前版本是候选来源"，
  不构成"当时读取的就是这一行"的证明；且当时题面来自多处数据
  （题干/解析来自 `question_content`，选项来自 `t_text_content` 的 JSON，答案来自 `t_question.correct`），
  **不能把部分字段的可能一致推导为整题一致**。
- **严禁**："没有发现变化"当作"证明没有变化"；把当前版本当作历史绑定写入。
- 本 Feature 的动作：把候选版本与依据记入迁移记录（题目 id、候选 `question_content.id`、依据、状态），
  **`question_content_id` 列保持 NULL**；要升级为「已证实」，必须先取得当时写入/读取路径的补充证据。
- 按 D-06 对未来的处理：确实无法恢复时显式标记"当时版本不可恢复"，不用当前版本补齐。

## 5. 回滚设计

| 阶段 | 回滚动作 | 切换后新增数据如何保留 |
| --- | --- | --- |
| 1 扩展结构 | 删索引 → 删列（顺序不可颠倒） | 列可空，删除不丢原有数据 |
| 2 回填 | 按批次标识删除回填行 | 新写入的版本行不属于回填批次，不受影响 |
| 4 读路径 | 开关切回旧路径 | 新旧表示同时存在，新增数据保留在权威表 |
| 5 旧写入退出 | 恢复旧写入开关 | 旧表示未删除，期间新增数据仍在 |

**逆向无损性评估**：`question_content → 旧 JSON/t_text_content` 的逆向转换**不保证无损**
（两条写入路径的序列化与 hash 算法不同，见 `entry-inventory.md` W-2/W-15）。
因此旧表示在**退役窗口内**只读保留、不删除（R-4）；窗口结束且 R-1～R-4 满足后按 R-5 删除——
**终点是单份权威表示，不是永久双份**。退役条件与时机见第 0.1 节，受 Q-08 阻塞。

## 6. 停写窗口与降级

- 建唯一索引（阶段 1）需要写锁：在低峰执行，并确认事务不会长时间占用 `question_content`；
- 回填期间：题库编辑入口限流或暂停（避免与回填竞争）；学生作答不受影响（读路径未切换）；
- D-17 绑定的写入路径上线后，**开始作答**是关键路径：绑定失败必须明确拒绝而不是降级放行。

## 7. 失败处理原则

- 单题失败隔离并保留原值；**不猜测修复**（D-10、plan 工作规则）；
- 任何"结论与数据不一致"的情况：**改结论，不改数据**；
- 每个失败样本都要能定位到 `question_id` 与失败原因，并进入人工处理清单。

**跳过/失败题目必须有闭环（四要素，缺一不可）**：

| 要素 | 要求 |
| --- | --- |
| **原因** | 记清形态与判定依据（例：缺 `version=1` 但已有 current，直接回填会使整批失败） |
| **处理责任** | 指定人或角色；未指定前不得视为已处理 |
| **重试方式** | 人工处理完成后如何重新入批（从跳过清单移除 + 重跑所属批次，保持幂等） |
| **最终去向** | 按三态口径（已证实 / 候选匹配、未证实 / 不可恢复）归类；归类完成前保持"跳过"，**不得自动补齐或自动绑定** |

**对账数字必须分列**：`本次迁移新增` / `原有内容` / `跳过未处理` 三栏，
不得用合并后的"覆盖率"掩盖被跳过的题目（`rehearsal-report.md` 第 3 节的口径警告）。

## 8. 对账报告格式（字段级）

| 字段 | 含义 |
| --- | --- |
| 批次号 / 代码提交 / 库名 / Flyway 版本 / 执行时间 | 可追溯性头部 |
| 处理题数 / 成功 / 跳过 / 失败 | 批次汇总 |
| 覆盖率 | 有权威内容的题目占比（当前基线：6613/6613，A-06） |
| 唯一 current | `0_current` / `1_current` / `multiple_current` 分桶（A-03） |
| 版本连续性 | 断号题数（当前：0，A-05） |
| 内容一致率 | 按题型分层，且必须说明是**抽样人工对照**还是**规则比对**（A-06 只给了分层规模） |
| 冲突样本 | 题目 id + 差异字段 + 原值保留位置，逐条列出 |
| 未执行项 | 显式列出，不勾选、不估算 |
