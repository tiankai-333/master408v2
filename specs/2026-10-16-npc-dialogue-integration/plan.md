# Plan — NPC 对话包接入与推理游戏闭环

## 任务组 1：固定可验证版本与一条交互

1. 只读核对另一位 Agent 的同步结果，定位目标仓库规则、提交、包元数据和游戏依赖方式。
2. 区分实际发布包与本地源码，确认本次要验证的产物和版本，不凭 README 推定一致。
3. 选择一个角色、一条条件触发规则和一次连续追问，写出允许/拒绝/失败的预期状态。
4. 列出现有可复用接口及缺口，确认最小示例、游戏接入和模型运行范围。

出口：能说明“测试哪个包、哪个应用、什么交互”，实施路径与权限明确；版本未明确时不先改外部工程。

## 后续任务组方向

- 从隔离的消费示例安装包产物，按公开接口完成对话与候选处理。
- 在游戏中接通状态变化与后续对话，必要时修正实际缺口，并同步契约说明。
- 测试关键失败、条件不满足与信息泄露场景，分别保存输出和状态，记录仍存在的限制。
- 形成接入说明、可重跑验证和应用演示；如果确需新版本发布，先明确发布范围与版本策略。
- 作者完成包边界、失败行为与接入实践考核。

本文件不指挥另一位 Agent，不直接将其他线程消息或源码同步状态当作已验证成果。
