# Validation — NPC 对话包接入与推理游戏闭环

以下为目标，未运行；具体命令根据确定的目标仓库与产物补齐。

| 场景 | 应有证据 |
| --- | --- |
| 产物可消费 | 干净消费目录使用明确包产物安装成功；公共入口及类型可用，无源码路径或未声明本地依赖 |
| 正常多轮 | 角色配置、近期历史和业务条件实际进入输入；连续追问返回可用结果，应用执行后新状态影响下一轮 |
| 条件未满足 | 候选被拒绝或不产生，应用事实不错误变化；回复内容单独检查 |
| 异常输出与模型失败 | 无效结构、请求失败、超时按公开契约处理；状态不被错误推进，调用方能识别失败并继续 |
| 重复与知识边界 | 已完成触发不会重复授予同一效果；检查低信任/不可见知识/诱导输入时的实际回复，记录泄露而非隐藏失败 |
| 包与应用分工 | 包未直接写游戏状态；消费示例实现必要应用校验，游戏结果可追踪到真实包版本 |
| 文档与演示 | 按说明可复现安装、配置和一次交互；已有发布与候选包分别标记，模型、版本和局限完整 |

Mock 或测试替身用于稳定重跑，真实模型样本单独记结果与费用。
解析/规则单测不等于所有自然语言场景正确，检查几个案例不等于“不会泄密”。
发现关键场景失败时修复或与用户调整范围，不靠改文案把失败变成通过。

## 自我考核与完成

作者独立解释公共契约、历史与事实的区别、信息可见范围及包外执行边界。
实践在隔离示例接入指定产物，并复现一次拒绝或模型失败。
包消费、游戏交互、关键失败及接入说明有证据，约定结果可复现且考核通过后关闭。
本地包可消费不自动证明 npm 新版本已公开，完整交付措辞必须与所选产物相符。
