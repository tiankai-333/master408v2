# Requirements — PromptOps 控制面

> 历史恢复：本文根据提交 `1fbc710`、Flyway V2、现有代码和测试于 2026-09-17 反向整理，
> 不是 2026-07-26 当时保存下来的原始需求。

## 背景

教学 Prompt 原先主要随代码发布，难以独立审查、灰度、回滚和追踪。需要在不把系统扩张成
通用 Skill 平台的前提下，为教学 Prompt 建立安全的运行时控制面。

## 范围

- Prompt 定义与具体版本分离；
- 支持草稿、提交、审批、灰度、全量发布和回滚；
- 发布前验证变量契约并支持在线测试；
- 按稳定哈希进行用户灰度；
- 支持 Kill Switch 和代码内兜底 Prompt；
- 记录管理操作审计日志；
- 模型调用记录实际解析到的 Prompt 定义和版本；
- 管理端支持版本查看、Diff、测试和发布操作。

## 非目标

- 不实现包含工具、权限和工作流的完整 Skill 平台；
- 不允许草稿直接承接生产流量；
- 不把 API Key 或用户敏感信息写入 Prompt；
- 不因数据库不可用而取消代码级安全兜底。

## 关键决策

- Prompt 标识与版本内容分表保存，发布状态单独管理；
- 发布是显式状态变更，不以“保存最新版本”等同于上线；
- 灰度分配使用稳定哈希，使同一用户在发布期间保持一致；
- Prompt Registry 是业务读取边界，上层不直接查询 Prompt 表；
- 管理接口要求管理员身份，所有状态变更写审计记录。

## 完成定义

管理者可以创建和测试版本，经审批后灰度或全量发布，并在异常时回滚或启用 Kill Switch；
运行请求能够追踪到实际 Prompt 版本，未发布内容不会进入生产调用。
