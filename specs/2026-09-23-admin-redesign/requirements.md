# Requirements — 管理端整体设计定稿

状态：**设计基线 v1.1（2026-09-24 修订）；实现尚未开始；作者自我考核未作答——Feature 未完成**。
v1.0（2026-09-23）完成整体设计；v1.1 按用户定位修订调整首版范围（见下方已确认决策）。
本 Feature 交付整体设计，不交付运行中的新管理端。

## 目标与已确认边界

用户决定彻底重建管理端，并要求先整体定型，避免逐页开发时反复改变数据与交互规则。
本 Feature 在开发前统一首版功能范围、信息架构、完整操作流程、接口契约、公共交互与切换方案。
“定型”指首版有可审查的设计基线，不承诺永不变更；后续变化须记录原因及影响。

- 不以旧菜单为新信息架构，但必须盘点现有能力，不能因换界面无声遗漏业务。
- 不建设复杂权限管理、角色编辑器、多级审批或 SSO；复用既有管理员授权与双端登录隔离。
- 保留已有 AI、PromptOps、评测与 RAG 能力，按实际实现设计管理入口，不重建引擎。
- 本轮不修改业务代码、不建生产页面、不执行数据库迁移、不删除旧表或旧管理端。
- 整体设计确认后，数据库、后端与前端另立配套实施任务，不能把设计完成当作接口已经可用。

## 已确认的设计选择

代理先提供有依据的推荐与代价，只向用户询问影响业务的选择。以下各项均已由用户确认：

- **A-01（2026-09-23 确认，2026-09-24 v1.1 修订）**：治理优先——题库、试卷、任务、答卷（只读）、
  账户、学科、消息、日志、AI 三页保留重建；开发者宣传页废弃；AI Agent 旧管理只读保留；
  知识点标注、用量明细、检索日志、评分、批量导入延后。
  **v1.1 修订：题目编辑器移出首版**（编辑权归属 AI 写入管道，编辑语义保留为管道契约；
  复启条件 = 管道落地后人工录入需求仍成立）。依据：用户确认"操作数据库的通常是 AI"，
  盘点佐证为编辑路径写入量可忽略、判断/填空表单 0 使用。
- **A-02（2026-09-23 确认）**：Vue 3 生态（与学生端同版本线）+ 新目录 `apps/frontend/admin-next`
  并行开发，旧端冻结为回归基线；用户要求完整说明技术栈，理由与备选否决见
  `architecture-and-cutover.md` §1。
- **A-03（2026-09-23 确认）**：四区 + 工作台导航，桌面优先，窄屏折叠不丢关键操作。
- **A-04（2026-09-23 解除阻塞）**：9.20 Q-08～Q-12 拍板（D-23～D-28）后不再阻塞本设计；
  剩余开放项（D-11 阈值、D-28 成因、U-9/U-10 量化）归实施验收。
- **A-05（2026-09-23 确认）**：整体切换 + ≥14 工作日回退窗口；部分切换仅作为推演结论保留

## 定位决策（2026-09-24，v1.1 核心）

用户确认：**操作数据库的通常是 AI**（批量导入与数据操作亦然），数据库治理必须从一开始就 AI 友好。
由此确定：

1. **管理端定位 = AI 运营数据库的控制面 + 巡检台**。四类职能：验收（人眼判断渲染正确性）、
   审计（版本/来源/写入者/作业记录）、巡检（常驻异常发现 + 工作台待办）、扳机（不可逆操作否决权）；
   并承担系统门面（mission 的"技术评审者"服务对象）。
2. **分工**：AI 管干活、数据库管拒绝、管理端管真话、人管扳机。
3. **AI 写入管道**：题目域的受约束写入路径（dry-run 校验 → 人工确认 → 幂等批量提交 → 作业记录），
   管理端界面与 dev-time AI Agent（经 CLI 壳）消费同一批端点；操作与协议分离，MCP 触发制
   （本 Feature 不引入，挂 roadmap M6 条件）。
4. **AI 友好数据库原则**（引用 9.20 已定稿决策，不另立标准）：约束在库里（D-13/D-14）、
   一事实一处（D-01/D-02）、内容机器可校验（D-23 schema）、写入可重试（D-10 幂等）、全程留痕
   （D-18/D-20 归属与审计）。
