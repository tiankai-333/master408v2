## 2. 公共交互规范（ADM-09）

### 2.1 加载 / 空 / 错误三态

| 状态 | 规范 |
| --- | --- |
| 加载 | 首屏表格/卡片用骨架屏；操作按钮提交中置 `loading` 并禁用重复点击（防重复提交的第一道闸） |
| 空 | 空态给"无数据 + 可执行动作"（如"暂无题目，新建题目"）；筛选无结果与无数据用不同文案 |
| 错误 | 列表区错误给"错误说明 + 重试"行内块，不弹全局遮罩；提交错误用消息条（见 2.4） |

### 2.2 分页与筛选

- 请求 `{pageIndex, pageSize, …filters}`，响应 `{list, total, pageNum}`（沿用现有分页契约）。
- 筛选条件变化回到第 1 页；筛选状态不写入 URL（首版简化），刷新后恢复默认。
- 默认页大小 20；日志/用量类 50。

### 2.3 表单规范

- 校验时机：字段失焦即时校验 + 提交前整体校验；错误定位到首个非法字段。
- 所有日期用 Element Plus 格式 `YYYY-MM-DD HH:mm:ss`（旧端 `yyyy-MM-dd` 缺陷不得带入）。
- **未保存离开拦截**：编辑页维护 dirty 标记；`onBeforeRouteLeave` + `beforeunload` 双拦截，
  弹"离开将丢失未保存的修改 [继续编辑] [放弃修改]"。保存成功后清除 dirty。
- **冲突后保留输入**（D-15）：任何保存失败（含版本冲突）不重置表单；
  冲突对话框提供"复制我的内容"兜底（把当前表单序列化为文本便于带出）。

### 2.4 反馈与确认分级

| 级别 | 操作示例 | 交互 |
| --- | --- | --- |
| L0 普通反馈 | 保存成功、测试成功 | 消息条（自动消失） |
| L1 一般确认 | 删除学科、停用供应商、发送消息 | 确认框：明确后果（如"广播不可撤回"） |
| L2 后果确认 | 题目停用（需填原因）、回滚 Prompt、提升发布 | 确认框 + 必填原因/备注，写入留痕 |
| L3 危险操作 | 紧急撤下、Kill Switch、删除供应商 | 二次确认对话框：输入对象名称才可提交；结果以审计留痕为准 |

### 2.5 错误与状态码处理（前后端双层）

- 业务层：响应 `{code, message, response}`；`code=1` 成功；`401` 未登录/会话过期 → 跳 `/login`
  （记录原目标，登录后回跳）；`403` 无权限 → 消息条"无权限"+ 保持当前页（不静默）；`5xx` → 消息条 + `requestId` 展示。
- HTTP 层：网络错误/超时/5xx 状态统一进同一错误通道；带 `requestId` 的错误必须原样展示 `requestId`（排障凭证）。
- 会话过期不弹多个：全局单例锁，30 分钟内只提示一次。

### 2.6 会话与安全显示

- 用户信息仅内存（Pinia）；刷新时经 `POST /user/current` 恢复，失败按未登录处理。
- API Key、密码等仅显示掩码；表单提交空密钥 = "不修改已有密钥"（沿用旧端语义）。
- 前端菜单显隐不构成权限；一切写操作以后端 `ROLE_ADMIN` 校验为准（ADM-08）。

## 3. 核心流程走查

每条流程给出：入口 → 正常路径 → 失败路径 → 恢复。标注对应的 validation 场景。

### F-01 登录、退出与会话过期（场景 1；ADM-08）

1. 管理员打开 `/admin-next/`（或任一受保护路由）→ 无会话 → 重定向登录页（记录原目标）。
2. 输入账号密码（可选"记住我"）→ `POST /api/admin/login` → 成功写入 admin 分区会话
   （`remember-me-admin` 仅勾选时）→ 回跳原目标 → 默认进工作台。
3. **同浏览器双端**：学生端已登录时管理员登录，两端身份互不覆盖（AUTH-01，后端分区保证）。
4. 退出：顶栏"退出" → `POST /api/admin/logout` → 清 admin 分区上下文与 `remember-me-admin` → 跳登录页。
   学生端会话不受影响（场景 1 断言）。
5. 失败路径：密码错误 → 登录页消息条，不跳转；账号停用（`LockedException`）→ 提示账号不可用。
6. 会话过期：任一请求返回 `401` → 单例提示 → 跳登录；登录成功回跳原目标。remember-me 有效时静默恢复。

### F-02 工作台（P1）

1. 登录后进入：4 张真实总数卡（`dashboard/index` `[已有]`）+ 待办列表（`overview/todos` `[待新增]`）。
2. 待办条目类型：RAG 对账缺口、`failed` 索引重试、停用题下游残留、待人工阅卷答卷。
   每条带计数与跳转（如"RAG 对账缺口 2,839 → 查看"）。
3. 失败路径：待办接口失败 → 待办区显示错误重试块；**总数卡仍可用**（两数据源独立）。
4. 红线：任何待办不可用时**不得显示"一切正常"**；统计口径在后端定义，前端不自算。

### F-03 题目列表（P2）

1. 筛选：ID / 关键词 / 学科 / 题型（1 单选 2 多选 **3 判断 4 填空** 5 简答）/ 状态（正常/停用/紧急撤下）/
   来源年份 / 就绪状态（展示、检索两列，见 F-11）。查询 `question/page` `[已有→待改：响应补 version/status/就绪摘要]`。
2. 行操作：预览（抽屉，`question/select/{id}`）、编辑、更多（版本历史、停用/恢复、紧急撤下）。
3. 列表短标题用 `title_text` 投影（DB-04）；不显示 `has_image`/`has_code`（TD-018 不可信，改显"资源引用数"或"资料未就绪"标记）。
4. 失败路径：查询失败 → 表格错误块 + 重试；无结果 → "调整筛选条件"空态。

### F-04 简单选择题：创建 → 预览 → 保存 → 重读（场景 2）

1. 列表"新建题目" → 选择题型（五型统一入口，默认单选）→ 进入 P3 编辑器（空表单）。
2. 填写：学科（必选）、难度、分值、题干块（HTML 原文）、选项行 A/B/C/D（可增删，prefix 自动生成），
   勾选唯一正确项。校验：所有选项非空、恰一项正确（服务端仍再校验）。
3. 预览：右侧预览面板实时渲染（与抽屉预览同组件）；`data-src` 外链图内联、缺失时显示降级文本 + "资料未就绪"标记。
4. 保存：`POST /question/edit`（`[已有→待改]`）→ 后端同事务写 `t_question` + 兼容表示 + `question_content`
   新版本行（v1，current，D-14）→ 返回 `questionId, version=1` → 消息条成功，dirty 清除，URL 变为编辑态。
5. 重读：刷新页面 → `question/select/{id}`（`[已有→待改：回显含 version]`）→ 表单回填与保存内容一致；
   来源面板显示空值（新建题无采集来源，显式为空，D-18）。
6. 失败路径：校验失败定位字段；网络失败 → 消息条 + 表单保留；服务端 5xx → 消息条含 `requestId` + 表单保留。

### F-05 复杂图文题编辑（场景 2 复杂侧；ADM-03）

编辑器按 D-23 块模型组织（简单题 = 只有一个 title 块 + 选项组的退化形态，两流程共用同一编辑器）：

1. 题干块（1 个）→ "添加公共材料"（0..n，材料块可命名"图 a/图 b"，顺序显式可拖拽）→
   "添加小问"（1..n：每个小问 = 题面 HTML + 分值 + 引用图块多选 + 独立答案）→
   每个小问下挂"解析"块（0..n，可回溯到小问，资源与题干隔离——DB-12：解析资源不得混入作答题面）。
2. 资源引用：块内 `data-src` 引用外部文件 + `data-fallback` 降级文本；引用列表显示可得性
   （存在/缺失/不可用，D-26 候选 9 列）；缺失时块标"资料未就绪"。
3. 样本口径：结构以真题 2024/43 的事实（公共材料两图 + 6 小问）为蓝本；夹具 FIXTURE-NOVA16-01
   为**原创同结构样本**（两图可独立寻址、小问记录顺序/分值/引图、答案归属小问、解析可回溯），
   **不冒充真题**。原图未核对（9.20 U-6 保真验证为"部分"），因此"图内容还原"不在本设计断言内，
   断言限于块结构与归属能力（3.9 规则 7）。
4. 保存与 F-04 相同：一次保存 = 一个新版本行（块 JSON 整体写入 `content_blocks`，D-23）；
   `*_text` 投影由后端重算，前端不提交。
5. 失败路径：块校验（`id` 唯一、`seq` 递增、`subOf` 只指向小问）在提交前拦截；答案块允许为空
   （D-28 合法状态，不告警，保存时显示"答案待补充"）。

### F-06 并发编辑与版本冲突（场景 3）

1. 管理员 A 打开题目 → 回显携带 `version=2`（打开编辑页时记录，D-16）。
2. 管理员 B 打开同题（同样 `version=2`）→ B 先保存成功 → 当前版本推进到 3。
3. A 提交（`expectedVersion=2`）→ 后端同事务内锁 `t_question` 行 → 读当前版本=3 ≠ 2 →
   拒绝，返回业务冲突码（非 500）。
4. A 端弹冲突对话框（见线框 W4）：说明"该题已被他人更新（当前 v3，你基于 v2）"；
   选项：**[保留我的内容继续编辑]**（表单不动，可复制全文后刷新对比）、**[放弃我的修改并刷新]**（重读 v3）。
   不提供自动合并（D-15：不自动合并、不静默覆盖）。
5. 兜底：即使前端漏带 `expectedVersion`，唯一键 `uk_question_content_version` 冲突（1062）也必须被
   翻译为同一冲突对话框，绝不显示 500（D-15/T2-2）。
6. 失败恢复：A 选择"保留输入"后可"另存为本地草稿"（浏览器本地，不入库——D-24 不做服务端草稿箱）。

### F-07 题目停用 / 恢复 / 紧急撤下（场景 4 管理侧）

1. 停用（L2 确认）：列表行"更多→停用" → 必填原因 → `POST question/disable`（`[待新增]`，
   写 `status=2` + 留痕三列）→ 行状态变"停用"。
2. 停用后逐场景行为（D-21 / 7.1，管理端展示口径）：
   - 新组卷选题弹窗不再出现该题（阻止新增入卷）；
   - 已组卷未开始的试卷：试卷详情顶部出现"包含 N 道已停用题目"提示条，提供"替换或确认保留"入口
     （替换属试卷编辑流程）；新的作答启动被后端拒绝；
   - 已开始作答：继续用已固定版本，不中途换题（依赖 D-17 绑定实施）；
   - 已完成答卷与历史：保持可读、评分不变；详情页题面角落标"该题已停用"；
   - 错题本/RAG：不再进入新练习推荐与检索证据（读时过滤，管理端在 RAG 状态页可见"已停用"标记）。
3. 恢复（L1 确认）：停用行"恢复" → `status=1` → 各下游可见性随读时过滤恢复；历史答卷不改写。
4. 紧急撤下（L3）：与停用**是两种操作**（D-21 末句）：`status=3` + 必填原因 + 输入题目 ID 二次确认；
   语义 = 因版权/安全立即全链路不可见；是否允许历史可读由产品在实施时确认（`physical-design.md` §7 边界），
   管理端文案在此前一律写"撤下后立即不可见"。
5. 失败路径：停用请求失败 → 状态不变 + 消息条；下游标记失败不回滚停用，但出现在工作台"停用残留"待办
   （7.3 标记+读时过滤+对账兜底）。

### F-08 题目版本历史（P4；D-02/D-24）

1. 入口：编辑器"历史版本"或列表行"版本历史" → `GET question/versions?questionId=`（`[待新增]`）。
2. 列表：版本号、是否 current、是否曾发布（`published`，置 1 不回退）、保存时间、操作人、变更来源
   （管理端编辑/回填/导入——按 D-18"人工修改另留记录"口径展示可得字段，缺失显式为空）。
3. 操作：任一版本只读预览；与当前版本逐块差异（文本层 diff）。
4. 边界：**不支持从历史版本"恢复"为新版本的一键操作**（会伪装成"时间机器"；如需以旧版为基础修改，
   用户走"复制到新编辑"，产生正常新版本并留操作记录）。此为 D-24 简化版本的代价，已在 UI 文案说明。
5. 不可恢复历史：早于版本体系的历史显示"该记录产生于版本体系建立前，无法恢复当时版本"（D-06）。

### F-09 试卷创建/编辑（P6）

1. 新建：学科、试卷类型、名称、建议时长；（考试卷类型显示起止时间窗，日期格式修正）。
2. 标题分组：添加"标题 N"→ 组内"添加题目" → 选题弹窗（按 ID/题型筛选、多选、分页；
   查询结果**不含停用/紧急撤下题**，D-21）→ 选中题目逐个 `question/select/{id}` 拉全量回显。
3. 组内题目可排序、可移除；题面用预览组件渲染（含资源内联）。
4. 保存：`exam/paper/edit`（`[已有]`）→ 试卷框架写 `t_text_content`（该语义仍是权威，D-03/D-27 整表保留）。
5. 失败路径：选题后题目被他人停用 → 保存时后端校验拒绝并列出题目 ID → 前端标红提示替换；
   网络失败表单保留（含已选题目）。

### F-10 历史答卷查看（P8；场景 4 学生侧）

1. 答卷列表：学生、试卷、学科、得分、状态（待批改/已批改/已完成）、提交时间；只读。
2. 详情（`[待新增]` 端点）：
   - 优先展示**作答绑定的内容版本题面**（D-17：开始作答时绑定 `question_content` 版本；
     实施落地前，旧记录按"候选匹配、未证实"口径处理——`physical-design.md` §8）；
   - 无绑定或不可恢复的旧记录：题面区显示"该次作答的题面版本无法恢复，以下为当前版本参考"并
     明确标"参考"（D-06：不用当前版本补齐历史）；
   - 每题显示：题面（绑定版本）、学生答案、判定结果；填空/简答显示"待人工阅卷"（当前恒 0 分事实）；
   - 96 类"无文本内容"作答显示"该次作答无文本内容"（A-10 定性：正常状态，非缺陷）。
3. 管理员在学生作答期间修改/停用题目（场景 4 交叉走查）：进行中的作答不换题（已固定版本）；
   已完成答卷评分不变；只有**新**作答用到新版本。此行为在答卷详情与题目停用确认文案中均有说明。
4. 失败路径：详情接口失败 → 错误块重试；部分题目缺绑定 → 逐题标记而非整页报错。

### F-11 资源与就绪状态（场景 5；ADM-06 / D-25）

管理端**绝不把四个维度混成一个绿灯**，状态矩阵在题目列表摘要、编辑器资源面板、RAG 状态页三处一致：

| 维度 | 数据来源（候选 10/9 列） | 展示 |
| --- | --- | --- |
| 展示就绪 | `display_ready`（块齐全 + 资源可得） | 题目列表状态点：绿=就绪；黄=资料未就绪（缺图/缺块），点开看缺口清单 |
| 检索就绪 | `retrieval_ready`（权威判定：存在 `indexed` 向量且 `source_content_version` 一致） | 独立列：绿=向量可用；灰="向量检索未就绪"（可恢复滞后）；红=`failed`（可重试） |
| 资源可得性 | `question_asset.availability`（0 未校验/1 存在/2 缺失/3 不可用） | 资源面板逐条显示；缺失项提示"题面将使用降级文本展示" |
| 停用状态 | `t_question.status` 1/2/3 | 独立标签；已停用题在 RAG 状态页标"不作为新检索证据" |

1. 典型场景走查（场景 5）：原图可展示（可得性=存在）但 RAG 加工失败（`rag_embedding.status='failed'`，含
   `error_message`）→ 题目详情：题面正常渲染；RAG 状态页该题行显示"检索未就绪：向量索引失败（错误信息），
   当前自动解答仅用词法召回"（D-25 矩阵第二行），并提供 **[重建该题索引]** 按钮。
2. 按钮可用性红线：后端尚无对应端点的操作**不渲染为可用按钮**（validation 场景 5"未实现操作不得伪装按钮可用"）——
   重试按钮仅在 `[待新增]` 的重试端点实现后启用；实现前显示说明文字。
3. "向量未就绪"与"无可用证据"文案严格区分（4.6）：前者"投影滞后，稍后重试或仅词法"，
   后者"检索无结果"；两者都不标为成功。

### F-12 模型与用量（P9）

1. 供应商列表（掩码 Key、启停开关 disabled-when-no-key、测试结果标签含 `lastTestMessage` 悬浮）。
2. 新增/编辑（L1 确认）：Base URL、模型三件套、优先级；保存 `provider/save`（空 Key=不修改）。
3. 测试：行内"测试" → `provider/{id}/test` → 成功/失败标签即时更新。
4. 删除（L3）：输入供应商代码确认（旧端无确认，升级）。
5. 用量卡：窗口切换（7/30/90 天）→ 汇总 4 指标 + 按供应商表 + 最近日志表；失败请求行可展开看错误消息。
6. 失败路径：测试失败不影响配置保存；用量接口失败 → 错误块（配置卡独立可用）。

### F-13 RAG 索引状态与重建（P5；`[待新增]` 为主）

1. 顶部汇总：应有投影数 / `indexed` / `failed` / 未就绪（对账缺口）——数字全部来自对账查询
   （基线参考：6613 ready / 3774 indexed / 40 failed，A-11）。
2. 按题查询：题号 → 展示/检索两状态 + chunk 数 + 最近索引时间 + `error_message`。
3. 重试：failed 行 [重建该题索引] → `POST ai-config/rag/index`（`[已有]`，范围=单题）→ 结果回显
   `{indexed, failed, …}`。
4. 批量构建：范围（题目/知识库）+ `force` + 上界 → L2 确认（显示影响规模与费用影响=embedding 调用）→ 触发。
5. 检索冒烟：查询串 + topK → `rag/search` `[已有]` → 命中列表（含来源引用），标注"此为冒烟测试，
   不代表线上质量"（质量结论归 Phase 4 评测）。
6. 失败路径：构建部分失败 → 逐题明细可见 failed 与原因；**不显示整体"成功"**（DB-14）。

### F-14 Prompt Studio（P10）

沿用旧端信息结构（定义左栏 + 版本/发布/审计三页签），交互按公共规范重建：

1. 选定义 → 版本列表（状态机：草稿/测试/待审批/已驳回/灰度/已发布/已退役）。
2. 新建草稿（克隆 active 或空白）→ 编辑（System/User 模板/变量/变更原因/风险说明必填）→
   Playground 测试（单次调用，显式"不消耗线上"说明）→ 提交审批（L0）→ 审批+初始灰度（L1）。
3. 灰度调比例（滑杆+应用）、提升发布（L2：确认"旧 active 将退役"）、回滚（L2）、Kill Switch（L3）。
4. Diff 弹窗（+/−/上下文行）；审计页签展示全部操作留痕（操作人/时间/版本迁移/备注）。
5. 失败路径：状态机拒绝（如对 active 编辑）→ 后端 400 消息原样展示；loading 缺陷（旧端 #8）消除。

### F-15 固定评测（P11）

1. 数据集卡：版本号、用例表（仅 model 用例可选；contract 用例只计数并注明"由 JUnit Mock 验证"）。
2. 启动：候选标签 + 范围 → L2 确认（费用警示，沿用旧端文案）→ `runs` 入队 → 轮询刷新（3s，仅 queued/running 时）。
3. 运行记录：状态、通过数、质量分、Token/费用估算、延迟 P50/P95 → 逐条证据弹窗（含模型回答与失败原因）。
4. 对比：选两个 completed run → 五项带符号差值（质量/通过/费用/延迟/P95）。
5. 失败路径：run `failed` → 明细可见失败用例与原因；**不在界面上把失败 run 计入对比候选**。

### F-16 账户、学科、消息、日志（P12～P15）

1. 账户：role 筛选（学生/管理员）合一列表；启停（L1）、编辑、重置密码（L2+新密码二次输入）、
   日志跳转（带 userId）。删除入口**默认不提供**（软删历史用户影响答卷关联语义，需求未提出）——
   若实施确认需要，按 L3 处理并另立决定记录。
2. 学科：CRUD；删除（L1）后端软删；被试卷引用时的行为沿用后端现状（不新增校验承诺）。
3. 消息：列表 + 详情（`[待新增]`）；发送（L1"广播不可撤回"确认，因后端无撤回端点）。
4. 日志：操作人/类型筛选，只读；不提供导出（后端无端点，不做伪装按钮）。

## 5. 复杂样本能力断言（对应 ADM-03 走查）

以 FIXTURE-NOVA16-01（原创夹具，结构同 2024/43：2 材料 + 6 小问）在 W3 编辑器上逐条断言：

| # | 断言 | 结果 |
| --- | --- | --- |
| 1 | 每题可持有 ≥2 个有序材料块且图号（图 a/图 b）可独立寻址 | 块模型 `seq` + `label` 满足（3.9 规则 7①） |
| 2 | 每个小问记录顺序、分值、所引图块标识与自己的答案 | `sub_question` 块 `score`+`assetRefs`+挂载 `answer` 块 |
| 3 | 解析与题干严格分离且可回溯到小问 | `analysis` 块 `subOf` 指向小问块；资源不混题面（DB-12） |
| 4 | 图块有独立资源身份与可得性；缺失时降级文本显式展示 | 资源面板逐条 `availability`；D-25 联动"资料未就绪" |
| 5 | 保存后重读：块结构、顺序、引图、分值、答案归属全部一致 | 一次保存=一个版本行（块 JSON 整体），追加式不可变 |
| 6 | 纯文本投影不混入图内标签 | `*_text` 后端按规则重算（U-10 规则），前端不提交投影 |

第 43 题原图核对状态：9.20 U-6 为"部分"（原图以 base64 内联于外部 HTML、作为文件不可获得）→
本设计的断言**不含图内容还原**，只含结构与归属能力；真题图片导入属实施与补采范畴（D-28 成因确认关联）。
