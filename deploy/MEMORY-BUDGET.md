# 内存预算表（PD-02）— 2 GiB 单机

状态：**本地演练已实测（2026-09-24，开发机 Docker Desktop，与 v1 栈并行运行）；服务器部署后须复测。**

机器事实：2 vCPU / 1.8 GiB 可见内存（inventory 实测 available 1.5 GiB）/ 无 swap →
部署第 1 组需创建 2 GiB swapfile（受控、swappiness=10）。

## 形态一：Qdrant 关闭（首期默认，A-02）

| 组件 | 上限 (mem_limit) | 预期常驻 RSS | 依据 |
| --- | --- | --- | --- |
| OS + 系统进程 | — | ~350 MiB | 2026-09-23 盘点实测（部署前基线） |
| mysql | 700 m | ~400–500 MiB | buffer_pool 128M + perf_schema OFF（small.cnf） |
| backend (JVM) | 768 m | ~450–600 MiB | 堆 ≤45%×768≈345M + Metaspace ≤192M + 线程栈 |
| redis | 128 m | ~30–50 MiB | maxmemory 64mb + 进程开销 |
| nginx | 64 m | ~10 MiB | 静态文件服务 |
| **合计上限** | **1660 m** | **~1240–1510 MiB** | 对 1849 MiB 物理内存留 ≥340 MiB 余量 + 2 GiB swap 兜底 |

## 形态二：Qdrant 开启（`--profile vector`）

| 组件 | 上限 | 说明 |
| --- | --- | --- |
| + qdrant | 512 m | 集合重建投影；上限内由 HNSW 内存需求决定，实测前不承诺 |
| **合计上限** | **2172 m** | **超出物理内存 → 必须依赖 swap，OOM 风险由该形态承担** |

结论（A-02 落地）：2 GiB 同机全栈 + Qdrant 是极限形态；首期关闭向量、走词法回退
（tech-stack 明确该降级路径合法），升配或验证实测有富余后再启用。
